## 0. 최종 목적

논문과 함께 코드를 공개했을 때, 처음 보는 사람도 구조만 보고 바로 이해하고 실행해볼 수
있는 상태를 만드는 것. 세 가지 축으로 진행한다:

1. **파라미터 단일화** — 어떤 스크립트도 자기 자신의 하드코딩된 기본값을 갖지 않는다.
   모든 실행 파라미터(축 설정, 실행 환경, 모델/학습 하이퍼파라미터 포함)는
   `parameters.py` 하나에서만 관리하고, 각 스크립트는 그 값을 참조만 한다. CLI 단축
   플래그·yaml 설정 파일 등 파편화된 기본값 소스를 없애 "같은 옵션 없음이 실행 경로에
   따라 다른 결과를 내는" 상황을 원천 차단한다.
2. **폴더 구조 = `run_pipeline.py` 스텝 순서** — 프로젝트 최상위 디렉터리 이름만 보고도
   전체 파이프라인 순서(1~10)를 알 수 있게 만든다. 스텝 전용 코드는 번호 폴더에,
   2개 이상 스텝이 공유하는 코드는 별도 공유 라이브러리 위치에 모은다.
3. **코드 크기 축소** — 메인 로직(현재 실제로 쓰이는 v4 파이프라인)은 유지하면서, 더는
   쓰지 않는 과거 버전(v0~v3)·미채택 실험(v5) 경로를 제거한다. 뒷 스텝(10_eval)부터
   앞 스텝(1_convert) 방향으로 거꾸로 진행 — 뒤쪽이 앞쪽 산출물에 의존하므로, 이 순서가
   호환성 깨질 위험이 가장 적다

## 3. 현재 진행 중인 사항

**방법론**: 스텝 순서(1→9)대로 스크립트를 열어, `main()`이 호출하는 하위 함수를
번호 주석으로 추적하면서 각 함수가 "실제로 무엇을 계산하는지"를 한 줄씩 검증한다.
문서/주석에 적힌 의도와 실제 코드가 하는 일이 다르면(=죽은 코드, 잘못된 비교
대상, 방향이 뒤바뀐 의존성 등) 그 자리에서 바로잡고 `docs/REFACTORING.md`에
근거(실측 수치, 재실행 검증)와 함께 기록한다.

| 파일 | 상태 | 비고 |
|---|---|---|
| `4_hi_analysis/hi_correlation.py` | ✅ 완료 | 4-파일 분할(constants/logics/plot) + CLI 제거 + 흐름 주석화 |
| `5_interaction/interaction.py` | ✅ 완료 | 가장 많은 불일치 발견(아래 참고) — Fisher 검정 죽은 코드, 유사반복 오류, 풀링 편향, `_load_all_scenarios` 소유권 방향 역전, 풀링 기준 진단 필드 전부 제거 |
| `6_synergy/synergy.py` | 🔶 부분 | `_load_all_scenarios` 소유권만 interaction.py로 이전(완료) — 자체 CLI 정리/함수 분해는 미착수 |
| `7_kernel/kernel.py`, `8_train/train.py`, `9_eval/test.py` | ⬜ 미착수 | |
| `1_convert/`~`3_integrity/` | ⬜ 미착수 | 1차 보고에서도 동일하게 남은 작업으로 명시됨 |

`5_interaction/interaction.py`에서 발견된, "생각과 달랐던" 대표 사례:

1. Fisher z-변환 검정 + Benjamini-Hochberg 보정 전체가 최종 판정에 **안 쓰이는
   죽은 계산**이었음(실제 판정은 처음부터 효과크기 기준). 원인 진단 결과 유사반복
   (세그먼트 행 수십만 건을 독립 표본처럼 취급)으로 표준오차가 수천 배
   과소추정돼 있었다.
2. 셀 단위 직접 계산으로 교체 후에도, "풀링된(여러 셀을 섞어 계산한) 효과크기가
   Cohen 0.1 문턱보다 체계적으로 작게 나온다"는 사실을 발견 — 66개 HI 전부에서
   풀링값이 셀 단위 평균보다 평균 2.6배 작았다(심슨의 역설류 희석).
3. 효과크기 문턱을 데이터 기반 귀무기준선으로 바꾸려는 두 차례 시도(분할-재계산,
   순열검정) 모두 실측으로 "변별력 없음"을 확인하고 폐기 — 최종적으로는 Cohen
   0.1 문턱 자체는 유지하되 비교 대상만(풀링값 → 셀 단위 평균) 교정하는 것으로
   귀결됐다.
4. `_load_all_scenarios`(공용 데이터 로더)가 Step 6(synergy.py)에 정의돼 있고
   Step 5(interaction.py)가 가져다 쓰는, 파이프라인 실행 순서와 거꾸로 된 의존
   방향이었음 — 발견 즉시 교정.

## 4. 남아있는 이슈

- **plot 모듈화**: `4_hi_analysis/plot.py`·`5_interaction/plot.py`는 이번
  리팩토링에서 "메인 스크립트가 저장한 JSON/CSV를 읽어 독립적으로 재실행 가능한
  시각화 모듈"이라는 공통 패턴으로 정리됐지만, `2_preprocess/`·`3_integrity/`·
  `9_eval/`의 `plot_*.py`는 아직 스텝마다 제각각인 구조(메인 스크립트에 플롯
  로직이 섞여있거나, 재실행 조건이 다르거나)로 남아 있다 — 통일할지, 어느
  수준까지 통일할지 결정 필요.
- **다중공선성 제거를 시나리오 분류기(SCR)에도 적용해야 하는가**: 현재
  `FIXED_MIN_PARTIAL_CORR`/`ACTIVE_SYNERGY_REDUNDANCY_THRESHOLD` 등 다중공선성
  배제 로직은 Step 6~8(시너지/커널 — 회귀 경로의 피처 생성)에만 적용되고,
  배포 시 세그먼트 내용물로 시나리오를 예측하는 분류기(SCR 배포 라우팅, 별도
  모듈) 쪽에는 적용돼 있는지 확인되지 않았다 — 분류기 feature set에도 같은
  배제 기준을 적용할지, 아니면 분류 목적상 오히려 중복 피처가 (판별력 측면에서)
  유리할 수 있는지 검토 필요.
- `6_synergy/synergy.py`·`7_kernel/kernel.py`·`8_train/train.py`·`9_eval/test.py`
  자체 CLI 제거 + 함수 분해(§3 참고) 미착수.
- `1_convert/`~`3_integrity/` 리팩토링 자체가 미착수(1차 보고 때부터 이어지는
  남은 작업).

## 5. 스텝별 요약 (`docs/PIPELINE.md` 기준)

- **Step 1 — 데이터 변환**(`1_convert/convert_unified.py`)
  - 원본 2종(MIT/HUST)을 공통 스키마로 통일
  - 전류 부호로 충/방전/휴지 단계를 판정
  - 셀 연결·불량셀 제외로 데이터 신뢰성 확보
  - 사이클·행 단위 품질 필터로 노이즈 제거
  - 출력: `_1_data_unified/{MIT,HUST}/{cell_id}.pkl`

- **Step 2 — 전처리**(`2_preprocess/preprocess.py`)
  - 결측·시간 역행 등 이상 사이클 정리
  - 통계 기반 이상치를 2중으로 제거
  - 물리적 범위를 벗어난 데이터 컷
  - segment_id 부여로 분석 단위 확정
  - 출력: `_4_data_hi/clean/{dataset}/*.pkl`

- **Step 3 — 무결성 검사**(`3_integrity/check_integrity.py`)
  - 데이터는 바꾸지 않고 검증만 수행
  - 로드 가능 여부·스키마·ID 일관성 확인
  - segment_id 채번 규칙 위반 탐지
  - 통계적 이상 징후를 WARN으로 보고
  - 출력: `integrity_report.csv`, `integrity_issues.csv`

- **Step 4 — 시나리오 분할 & HI 추출**(`4_hi_analysis/hi_correlation.py`)
  - 파이프라인의 핵심 특징공학 단계
  - q_frac 기준 충/방전 구간을 3존 분할
  - 분할 조합으로 6개 시나리오 정의
  - 라벨 누수 방지용 q_frac_ref 축 사용
  - 시나리오별 세그먼트에서 HI 66개 추출
  - 출력: `_4_data_hi/{axis}/seg,cycle/{dataset}/*.pkl`

- **Step 5 — Interaction test**(`5_interaction/interaction.py`)
  - HI 개념별 시나리오 의존성 검정
  - 시나리오 간 상관 변동폭을 측정
  - 변동폭 크기로 게이트 방식 결정
  - 출력: `hi_scenario_interaction_{tag}.json`

- **Step 6 — Synergy grouping**(`6_synergy/synergy.py`)
  - HI를 상관 높은 순으로 그리디 결합
  - 다중공선성 배제로 중복 HI 방지
  - 편상관 기준으로 그룹 성장 여부 판단
  - 출력: `synergy_groups_{tag}.json`

- **Step 7 — Kernel HI 생성**(`7_kernel/kernel.py`)
  - 시너지 그룹을 비선형으로 재결합
  - 커널 회귀 예측값을 새 HI로 추가
  - 커널 간·원본과의 중복을 기록만
  - 출력: `kernel_group_features_{tag}.pkl`, `_combined_redundancy.json`

- **Step 8 — 모델 학습**(`8_train/train.py`, SCR 모델)
  - 학습 가능한 게이트로 HI를 자동 선택
  - 회귀+분류+희소화 손실을 함께 학습
  - 게이트 포화도 기준으로 체크포인트 채택
  - 출력: `checkpoints/best_by_saturation.pt`, `config.yaml`, `gates/*.json`

- **Step 9 — 평가**(`9_eval/test.py`)
  - 시나리오 라벨 없는 배포 상황을 가정
  - oracle/hard/soft 3가지 라우팅을 비교
  - SOH 오차지표와 시나리오별 분해 산출
  - 출력: `metrics/metrics.json`, `predictions/*.csv`, `figures/*.png`
