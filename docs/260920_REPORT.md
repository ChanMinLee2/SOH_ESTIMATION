## 안건 1 — 기존 v4 구조의 오류 수정들 (2026-09-17 이후)

### 내용

`docs/260917_RESULTS.md`(커널 own-scenario 제한 + 결합 다중공선성 배제) 점검이 v4 구조의
여러 결함을 추가로 드러냈다. 동작이 실제로 바뀌는 로직 수정만 요약:

1. **커널 HI L0 페널티 완전 누락 수정** — 커널 게이트에 희소화 압력이 아예 없어 시나리오당
   16~24개가 거의 다 선택되고 있었음. => 2번으로 해결
2. **커널 HI own-scenario 제한** — 다른 시나리오 값이 커널 컬럼에 섞이던 문제 => 각 시나리오가 생성한 커널 HI만 사용할 수 있도록 수정
3. **결합(raw+kernel) 다중공선성 배제 신규 추가** — 전역 배제(`*_combined_redundancy.json`). 2번에서 생성한 커널 + raw HI들을 대상으로 다중공선성(0.9이상) 제거 
4. **위 2·3을 데이터 레벨 → 게이트 구조 레벨로 강제** — 데이터만 0으로 죽이는 걸로는 게이트가
   배제된 HI를 계속 "선택"하는 걸 못 막아, 커널은 `kernel_hi_counts`로 슬롯 자체 제거, raw는
   `redundancy_mask`로 게이트 출력을 항상 0으로 강제.
5. **다중공선성 배제가 분류기 입력까지 오염시키던 버그** — `forward()`가 `x = x_hi * nan_mask`를
    분류기(`probe_x`)와 회귀(`scen_x`) 양쪽에 공유하는데, 회귀용 다중공선성 배제가 이 공유
    `nan_mask`를 입력 레벨에서도 0으로 이중 강제하고 있어 분류기 입력까지 지워버렸다(게이트
    레벨 `redundancy_mask`만으로 회귀 정확성은 이미 충분히 보장돼 불필요한 이중 처리였음).
    실측 영향 큼: 이 로직 추가 전 분류기 정확도 98.65% → 추가 후 36~67%로 붕괴. 입력 레벨
    마스킹 함수를 삭제해 수정
6. **커널 L0 비용에 카테고리 가중치 적용** — 균일 비용 → 멤버 raw HI 카테고리 비용 평균.
7. **체크포인트 선택 기준 역전** — 기존 : sat 1순위 → 현재 : val_rmse 1순위(epsilon
   이상 개선 시), 아니면 sat 낮은 쪽 채택(val_rmse 상한 없음).
