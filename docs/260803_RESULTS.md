# 260803 — RawCNN 아키텍처 분석: `_ResBlock1d`·`AttentionPool1d`의 의미와 영향

`5_model/models/raw_cnn.py`의 `RawCNN`(방안2(a)/(b)가 `scr_model.py`에 붙이는 CNN 인코더,
`docs/260801_RESULTS.md` §0.5 참고)을 구성하는 세 요소 — Conv stem, `_ResBlock1d`,
`AttentionPool1d` — 를 코드 기준으로 뜯어보고, 각각이 무슨 의도로 들어갔고 실제로 어떤
영향을 미치는지 정리한다. 설계 의도는 `docs/MODEL_SPECS.md` §4.1(원 설계 문서)에 이미
근거가 적혀있어 그걸 그대로 인용하고, "영향"(효과) 부분은 이번 세션에서 실측한
`raw_embedding_analysis`/성능 비교 결과와 연결해 해석한다 — **이 연결 부분은 어블레이션
(예: AttentionPool을 avg-pool로 바꿔 직접 비교)으로 검증된 게 아니라 정성적 가설**이라는
점을 미리 밝혀둔다.

---

## 0. 전체 구조 — 텐서 흐름과 파라미터 수

```
입력 x_raw: (B, 2, 48)   — 채널=[V, |I|], q_frac [0,1] 정규화 그리드 48포인트

stem   : Conv1d(2→32,k=7,pad=3) → BN(32) → GELU → MaxPool1d(2)      → (B, 32, 24)
res1   : _ResBlock1d(32)                                             → (B, 32, 24)
down   : Conv1d(32→64,k=3,pad=1,stride=2) → BN(64) → GELU            → (B, 64, 12)
res2   : _ResBlock1d(64)                                             → (B, 64, 12)
pool   : AttentionPool1d(64)                                         → (B, 64)
proj   : Dropout(0.1) → Linear(64→64) → GELU                         → (B, 64) = cnn_emb
```

| 구성요소 | 출력 shape | 학습 파라미터 수 | 비고 |
|---|---|---:|---|
| stem | (B,32,24) | 544 | Conv(448+32bias) + BN(64) |
| res1 (`_ResBlock1d(32)`) | (B,32,24) | 6,336 | Conv×2(3,104×2) + BN×2(64×2) |
| down | (B,64,12) | 6,336 | Conv(6,208) + BN(128) |
| res2 (`_ResBlock1d(64)`) | (B,64,12) | 24,960 | Conv×2(12,352×2) + BN×2(128×2) |
| pool (`AttentionPool1d(64)`) | (B,64) | 65 | Linear(64→1) |
| proj | (B,64) | 4,160 | Linear(64→64) |
| **합계** | (B,64) | **42,401** | `raw_cnn.py` 자체 실행(`python -m models.raw_cnn`)으로 검증 완료 |

시퀀스 길이는 **48 → 24(stem MaxPool) → 12(down stride=2) → 1(AttentionPool로 압축)**로
줄어들고, 채널은 **2 → 32 → 64**로 늘어난다 — "공간 해상도를 줄이는 대신 채널(=표현
다양성)을 늘린다"는 표준 CNN 설계 패턴이다.

---

## 1. Conv stem — `Conv1d(2→32,k=7) → BN → GELU → MaxPool1d(2)`

**의미**: 첫 레이어가 48개 중 **7개 폭의 넓은 커널**로 시작한다 — 전체 길이(48)의 약
15%에 해당하는 넓은 국소 구간을 한 번에 훑어, 개별 포인트 잡음보다 **곡선의 대략적인
기울기/굴곡 패턴**을 먼저 잡아내려는 의도로 읽힌다(일반적인 CNN에서 stem에 상대적으로
넓은 커널을 쓰는 것과 같은 관례).

**영향**:
- **`BatchNorm1d(32)`가 이 세션에서 여러 번 확인한 "raw 입력 정규화"의 실체다** —
  `raw_v`(~3~4V)와 `raw_i`(~0~5A)는 스케일이 전혀 다른데, 이 첫 BN이 채널별로 학습된
  평균/분산을 빼고 나눠서 스케일 차이를 흡수한다(`docs/260801_RESULTS.md` §0.5에서
  "raw 곡선 정규화는 RawCNN 내부 BatchNorm1d가 담당"이라고 정리한 부분이 바로 이 레이어).
  이게 있어서 raw_v/raw_i를 CNN에 넣기 전에 별도 z-score를 안 해도 되는 것이다.
- **`MaxPool1d(2)`가 48→24로 절반을 버린다** — 그 구간에서 가장 강한 반응만 남기고
  나머지는 버리므로, 미세한 위치 정보 일부를 이 시점에 이미 잃는다. 이건 "약간의
  잡음/미세 시프트에 둔감해진다"는 장점과 "정말 미세한 국소 신호(예: 매우 좁은 knee)는
  이 단계에서 이미 뭉개질 수 있다"는 단점을 동시에 가진다 — 어느 쪽이 우세한지는
  이 프로젝트에서 직접 검증된 바 없다.

## 2. `_ResBlock1d` — 잔차 블록 (res1: 32채널/24길이, res2: 64채널/12길이, 총 2개)

```python
h = self.act(self.bn1(self.conv1(x)))   # Conv-BN-GELU
h = self.bn2(self.conv2(h))             # Conv-BN
return self.act(h + x)                  # x(입력)를 더한 뒤 GELU — 잔차 연결
```

**의미**(`docs/MODEL_SPECS.md` §4.1 원 설계 근거 인용): "LFP 세그먼트의 V-Q 곡선은
국부적 특징(**플래토 진입/이탈 기울기, knee point**)이 SOH에 민감하다"는 전제 아래,
"단순 conv → avg-pool" 대신 채택된 구성요소다. 잔차 연결(`h + x`)의 핵심은 **conv
브랜치가 입력을 통째로 다시 만들 필요 없이, 입력에 "더할 보정값(delta)"만 학습하면
된다**는 것 — 즉 "이 구간은 원래 곡선 그대로 두되, 여기 knee 부분만 강조해서 더한다"는
식의 **국소적 미세 조정**을 표현하기에 자연스러운 구조다. 곡선 대부분은 완만하고 knee/
plateau 전환부만 국소적으로 급변한다는 LFP V-Q 곡선의 특성과 잘 맞는다는 게 원 설계
의도다.

**영향**:
- **그래디언트 흐름**: `h+x`의 `x` 경로는 conv를 거치지 않고 그대로 역전파되므로,
  `res2`(입력에서 stem+res1+down을 거쳐 이미 여러 레이어를 통과한 지점)까지 그래디언트가
  감쇠 없이 전달될 수 있다 — 이 네트워크 자체는 깊지 않아서(전체 6개 conv 레이어) 잔차
  연결이 없어도 그래디언트 소실이 심각할 정도는 아니지만, 있으면 학습 안정성 면에서
  손해 볼 이유는 없다.
- **두 번 반복되는 이유**: res1(32채널, 아직 downsample 전 — 원본에 가까운 공간
  해상도)과 res2(64채널, downsample 후 — 더 추상화된 표현) 두 스케일에서 각각
  "국소 정제"를 한 번씩 거치게 한 것 — 낮은 레벨(세밀한 위치)과 높은 레벨(압축된 표현)
  양쪽에서 정제 기회를 준다는 뜻.
- **(a)/(b) 임베딩 차이와의 연결(가설)**: 이번 세션 `analyze_raw_embeddings.py`
  결과에서 (a)(분류기, frozen)와 (b)(회귀, 별도 학습) 임베딩의 코사인 유사도가 조합마다
  거의 0이거나 음수로 나왔다(`0.005~-0.18`, qfw+transformer 정정 후엔 `+0.24`). 잔차
  블록은 "입력에 무엇을 더할지"를 손실 함수에 맞춰 학습하는 구조이므로, **분류
  손실(scenario CE)이 요구하는 "국소 보정"과 회귀 손실(SOH MSE)이 요구하는 "국소 보정"이
  서로 다르면 두 res block이 서로 다른 delta를 학습해 최종 임베딩이 갈라지는 것은
  구조적으로 자연스러운 결과다** — 이 블록 자체가 "목적에 맞게 무엇을 강조할지"를
  유연하게 학습하는 부품이기 때문에, 오히려 (a)/(b) 간 표현 차이를 만들어내기 쉬운
  지점이라고 볼 수 있다(검증되지 않은 해석).

## 3. `AttentionPool1d` — 어텐션 풀링

```python
def forward(self, x):                  # x: (B, C=64, L=12)
    x_t = x.transpose(1, 2)            # (B, 12, 64) — 위치를 시퀀스 축으로
    w   = self.score(x_t).softmax(dim=1)   # 위치별 스칼라 점수 → 12개 위치에 대해 softmax
    return (x_t * w).sum(dim=1)        # 가중합 → (B, 64)
```

**의미**(`docs/MODEL_SPECS.md` §4.1 원 설계 근거 인용): "단순 avg-pool은 이 국부 특징을
희석시킨다" + "Attention Pooling은 **어느 q_frac 위치가 중요한지 학습한다** → HI와
상보적". `res2`를 통과한 뒤 남은 12개 위치(원본 48포인트를 stem+down에서 4배
다운샘플한 것) 각각에 대해 `Linear(64,1)`로 "이 위치가 얼마나 중요한가"라는 스칼라
점수를 매기고, `softmax`로 정규화해 가중합한다 — **모든 위치를 균등하게 반영하는
평균 풀링과 달리, 중요한 위치(예: plateau/knee가 걸린 구간)에 더 큰 가중치를 실을 수
있다.**

**영향**:
- **평균 풀링을 포함하는 상위 집합**: 모든 위치에 동일한 가중치(1/12)를 주는 것도
  `score`가 학습을 통해 도달할 수 있는 한 지점이므로, 이론적으로 attention pooling은
  평균 풀링보다 표현력이 절대 못하지 않다. 다만 그만큼 파라미터(65개, 미미한 수준)와
  **과적합 자유도**가 늘어나 학습 신호가 약하면 의미 없는 위치 강조 패턴을 학습할
  위험도 같이 늘어난다.
- **해석 가능성**: `score`가 만든 가중치 `w`(12개 값)를 시각화하면 "이 세그먼트에서
  모델이 어느 q_frac 구간을 가장 중요하게 봤는지"를 직접 볼 수 있다 — 이건 이
  프로젝트가 반복적으로 강조해온 "리뷰어 설득력/해석 가능성"(`REGRESSION_UPGRADE.md`
  §3.3: "AttentionPool1d가 어느 q_frac 위치가 중요한지 학습하므로 어텐션 가중치를 직접
  시각화해 해석 가능")의 근거가 바로 이 레이어다. **다만 이번 세션에서 이 가중치
  자체를 실제로 뽑아 시각화해본 적은 없다** — `raw_embedding_analysis`는 최종 `cnn_emb`
  (풀링 이후)만 비교했지, `score`의 중간 출력(어느 위치를 봤는지)까지는 안 봤다. 필요하면
  `model.raw_cnn.pool.score`에 forward hook을 걸어 바로 추출할 수 있다.
- **(a)의 "분류 목적 압축" 가설과의 연결**: `attention pool`이 "어느 위치가 중요한가"를
  학습하는 기준은 결국 그 위 손실 함수다 — (a)는 시나리오 분류(CE) 손실로 학습됐으므로,
  이 레이어가 강조하도록 학습한 위치는 "이 세그먼트가 chg_lo인지 chg_mid인지 구분하는 데
  중요한 위치"이지 "SOH를 정밀하게 추정하는 데 중요한 위치"가 아닐 수 있다 — 이번 세션
  §0.5/§11에서 반복적으로 나온 "(a)가 분류 목적으로 압축된 표현이라 회귀엔 손해"라는
  해석의 **구체적인 메커니즘 후보가 바로 이 어텐션 가중치 학습 지점**이라고 볼 수 있다.

## 4. 최종 `proj` — `Dropout(0.1) → Linear(64→64) → GELU`

**의미**: `AttentionPool1d`가 뽑아낸 64차원 요약 벡터를 한 번 더 선형 변환해 최종
`cnn_emb`으로 내보낸다 — `d_out=64`를 HI 64차원과 맞춘 것은 "HI와 동등한 예산의 정보
소스"라는 의도적 설계다(`raw_cnn.py` 주석: "HI 64D와 정렬").

**영향**: 이 레이어 자체엔 정규화가 없다 — `docs/260801_RESULTS.md` §0.5에서 이미
확인했듯 `cnn_emb`은 `feat`에 concat되기 전 **아무 정규화도 거치지 않는다**(방안1의
`raw_flat`엔 `BatchNorm1d(96)`을 별도로 추가했지만 (a)/(b)엔 대응하는 게 없음). 이번
세션 `raw_embedding_analysis`에서 (a)의 임베딩 분산이 (b)보다 4~184배 크게 나온
것(`docs/260801_RESULTS.md`/직전 대화 참고)이 바로 이 지점 때문일 가능성이 있다 —
`Dropout→Linear→GELU`는 출력 스케일을 특정 범위로 강제하지 않으므로, 분류(CE, 클래스
마진을 벌리려는 경향) 손실로 학습된 (a)와 회귀(MSE) 손실로 학습된 (b)가 서로 다른
출력 스케일에 정착해도 이상하지 않다.

## 5. 검토됐다가 기각된 대안 — 멀티스케일 병렬 CNN

`docs/MODEL_SPECS.md` §4.1이 실제로 비교 검토했던 대안:

```
병렬 브랜치: Conv1d(k=3)/Conv1d(k=7)/Conv1d(k=15) 각각 → GlobalAvgPool → concat
```

여러 커널 크기를 병렬로 두면 구현이 단순하고 병렬화가 쉽지만, **"각 브랜치가 독립적으로
학습되어 세그먼트 내 위치 관계(연속성)를 무시한다"**는 단점 때문에 기각되고, 지금의
"Residual(순차적으로 깊어지며 위치 관계를 유지) + Attention Pooling"이 채택됐다. 이
프로젝트에서 멀티스케일 버전을 실제로 구현·비교한 적은 없다 — 순수 설계 단계의
검토였다.

---

## 6. GELU를 쓰는 이유

`RawCNN`은 stem, ResBlock 내부(×2), downsample, proj 등 **모든 활성화 함수 자리에
`nn.GELU()`를 쓴다** — `ReLU`는 한 곳도 없다. 다만 이건 `raw_cnn.py`만의 독자적 선택이
아니라 **이 프로젝트 전체의 활성화 함수 컨벤션**이다: HI 인코더 MLP(`HI_EXPLAIN.md`
72/84/134/145행 — probe encoder, scen encoder 등)와 `CNNProbeClassifier`의 분류
head(`MODEL_SPECS.md` §4.2, 258/261행)까지 예외 없이 `GELU`를 쓴다. 이 CNN이 GELU를
선택한 별도의 근거가 문서화된 적은 없다 — "왜 CNN만 GELU인가"가 아니라 "이 프로젝트가
학습 가능한 모든 모듈에서 GELU를 기본값으로 쓰는데 CNN도 그 컨벤션을 따른다"는 게
정확한 설명이다.

그 컨벤션 자체의 일반적 근거(이 프로젝트가 명시적으로 논의한 적은 없지만, GELU가
ReLU 대신 현대 아키텍처의 기본값으로 널리 쓰이는 이유):

- **음수 입력에서도 완전히 0이 되지 않는다** — `ReLU(x)=max(0,x)`는 음수 구간에서
  그래디언트가 정확히 0이라 그 뉴런이 "죽으면"(dead neuron) 다시 살아나기 어렵다.
  `GELU(x)=x·Φ(x)`(Φ=표준정규 CDF)는 음수 구간에서도 작지만 0이 아닌 그래디언트를
  유지해 이 위험을 줄인다. 이 네트워크는 6개 conv 레이어로 얕은 편이라 dead
  ReLU 문제가 치명적일 정도로 심각할 가능성은 낮지만, 방지 비용이 거의 없다
  (`ReLU`와 계산량 차이는 무시할 수준).
- **매끄러운(smooth) 곡선** — `ReLU`는 0에서 꺾이는 점(kink)이 있는 반면 `GELU`는
  전 구간에서 미분 가능하다. 이 네트워크처럼 잔차 연결이 여러 번 누적되는 구조에서
  손실 지형(loss landscape)이 상대적으로 매끄러워질 수 있다는 것이 GELU/Swish류가
  Transformer·최신 CNN에서 ReLU를 대체하며 채택된 일반적 근거다.
- **실측 검증은 없음**: 이 프로젝트에서 `GELU`↔`ReLU` 교체 어블레이션을 실행한 적은
  없다 — 위 근거는 일반적으로 통용되는 이유이지, 이 데이터셋에서 GELU가 ReLU보다
  우월하다는 것이 실측으로 확인된 사실은 아니다.

## 7. t(dt/시간) 정보를 원본 데이터 처리에 쓰지 않은 이유

CNN 입력은 `RAW_CH=2`(`5_model/utils/hi_schema.py:50`) — **V, |I| 두 채널뿐이고
t(시간)는 들어가지 않는다.** 이건 "빠뜨린" 게 아니라 `docs/REGRESSION_UPGRADE.md`
§8.1이 2026-07-30에 검토한 뒤 **의도적으로 보류**한 것이다. 근거를 코드 흐름과 함께
정리하면:

**(1) 순증분 정보가 제한적일 가능성이 높다.** q_frac 그리드 위에서
`dq = I·dt`이므로 `dt/dq_frac ≈ q_tot/(48·I(q_frac))` — 세그먼트 내부의 상대적
시간 페이싱은 이미 CNN에 들어가는 `|I|` 곡선으로부터 conv가 암묵적으로 근사
학습할 수 있는 관계다. t를 별도 채널로 명시적으로 주는 것의 한계 이득이 작을
수 있다는 것이 첫 번째 이유.

**(2) 넣으려면 V/I와는 다른 방식의 처리가 필요해서, 안 넣는 쪽이 더 간단하고
안전하다.** `_resample_segment(vs, ims, qcs)`(`4_hi_analysis/hi_correlation.py:336`)가
지금 실제로 하는 일을 보면, **정규화가 적용되는 건 Q 하나뿐**이다 — Q는
`q_rel=(qcs-qcs[0])`, `x=q_rel/q_rel[-1]`로 시프팅+스케일링해 `[0,1]` 좌표축으로만
쓰이고, 그 좌표축 위에 V/I는 원본 물리값(Volt/Amp) 그대로 보간되어 얹힌다. 값 자체는
정규화되지 않는 이유는 전압은 화학종이 정하는 범위에, 전류는 프로토콜이 명령한 값에
묶여 있어 절대 스케일 자체가 SOH를 직접 누설하지 않기 때문이다.

t는 성격상 V/I 쪽이 아니라 **Q 쪽 부류다** — 절대 지속시간 자체가 SOH와 상관되는
변수라는 점에서 Q와 같다. 그대로 원본 값으로 보간하면 **두 종류의 누출**이 생긴다:

- **절대 위치 누출**: 세그먼트 시작 시각 자체가 "테스트가 얼마나 진행됐는가"(≈대략적
  노화 정도)를 곧바로 알려준다. → `t - t[0]` 시프팅으로 해결 가능.
- **지속시간(스케일) 누출**: 시프팅만으로는 안 끝난다 — 시프팅 후 지속시간
  `t_shifted[-1]=t[-1]-t[0]`(=원래 지속시간)이 그대로 보존되는데, CC 구간에서
  세그먼트 지속시간은 그 세그먼트의 절대 Q(≈SOH 상관)와 거의 선형이다. 건강한 셀은
  같은 q_frac 구간을 `[0,...,200]`초에 돌고, 노화된 셀은 정전류 하에 더 오래 걸려
  `[0,...,800]`초 — CNN이 "48개 그리드 끝값이 얼마나 큰가"만 봐도 지속시간(≈절대
  Q)을 그대로 읽어낼 수 있다. 이건 `stat_q_abs`/`stat_energy_seg`를 leak_cols로
  이미 배제한 것과 **같은 성격의 간접 누출**이 시간 채널로 재발하는 것이다.

즉 넣으려면 `t_rel = (t-t[0])/(t[-1]-t[0])`로 Q와 동일한 시프팅+스케일링을 거쳐야
하고, V/I처럼 "원본 그대로 보간"하면 안 된다 — **구현이 한 줄 더 필요하고, 잘못
구현하면 라벨 누출을 재도입할 위험이 있다.** 반면 기대 이득(1번 근거)은 크지 않다고
판단해, 지금은 **의도적으로 빼둔 상태**다.

**넣을 근거가 남아있는 유일한 지점**: `HI_DESCRIPTION.md`가 명시한 "HUST 다단계
C-rate 포착" — 48점 리샘플 `|I|`가 뭉갤 수 있는 급격한 전류 계단 전환을,
`t_rel(q_frac)` 매핑이 더 날카롭게 보여줄 가능성. 우선순위는 낮게 책정돼 있고, 넣게
되면 `RAW_CH`를 2→3으로 늘리고 V,I만 대비 V,I,t_rel 3채널 ablation으로 별도 검증할
항목으로 `REGRESSION_UPGRADE.md` §8.1에 이미 남겨져 있다. 이번 세션 기준 미착수.

## 8. 종합 — 이번 세션 실측과의 연결, 그리고 남는 질문

1. **BatchNorm(stem)이 raw 입력 스케일 문제를 이미 해결하고 있다**는 건 이번 세션에서
   코드로 확인된 사실이다("사전 정규화 추가 검증 필요성" 논의에서 이미 결론 남).
2. **ResBlock/AttentionPool이 (a)/(b) 임베딩을 서로 다른 방향으로 밀어붙이는 구조적
   여지를 갖고 있다**는 건 그럴듯한 설명이지만, 이 문서의 §2/§3 "영향" 항목에 적은
   해석은 **전부 가설**이다 — 실제로 검증하려면 (i) `score`(어텐션 가중치) 자체를
   (a)/(b) 사이에서 비교하거나, (ii) ResBlock을 제거한 축소판과 성능을 비교하는 식의
   추가 어블레이션이 필요하고, 이번 세션에서는 하지 않았다.
3. **`cnn_emb` 출력에 정규화가 없다는 점(§4)은 가설이 아니라 코드로 확인된 사실**이고,
   지난 대화에서 "사전 정규화보다 우선순위가 낮다"고 판단했던 것을 "출력 정규화는
   오히려 근거가 있다"로 수정하는 계기가 됐다(직전 대화 참고) — 이 문서의 §4가 그
   판단이 정확히 어느 레이어를 가리키는지 코드 수준에서 다시 확인해준다.
4. **GELU(§6)는 CNN만의 선택이 아니라 프로젝트 전체 컨벤션**이고, 이 프로젝트에서
   ReLU 대비 실측 검증된 적은 없다.
5. **t/dt 미사용(§7)은 실수가 아니라 2026-07-30에 근거를 남기고 보류한 결정**이며,
   "넣으려면 Q와 같은 시프팅+스케일링이 필요하고 안 하면 라벨 누출이 재발한다"는
   구체적 리스크가 이미 문서화돼 있다.

원본 코드: `5_model/models/raw_cnn.py`(전체 113줄), 설계 근거: `docs/MODEL_SPECS.md`
§4.1(라인 180~242). 파라미터 수 검증: `python -m models.raw_cnn`(5_model/ 내에서 실행,
출력 `params=42,401`).

## 9. 이 CNN 구조가 "풀사이클에서 부분적으로 잘라낸" 세그먼트 데이터에 적합한가

`_4_data_hi/full_cycle`(`common/scenario/full_cycle.py`)은 실은 **자르지 않은**
축이다 — `q_frac_lo=0.0, q_frac_hi=1.0`로 방향(충/방전)당 전체 curve 1개를 통째로
세그먼트로 쓰는, "부분 관측 대비 상한선(ceiling)"용 베이스라인(`docs/PIPELINE.md`
§1-A)이다. 실제 프로덕션 실험(`q_frac_wide`/`vqslope`/`q_abs`)이 쓰는 세그먼트는
`q_frac_wide.py`(85-91행)의 `n2=0.2`(기본값, `qfw_35%_20%`의 `20%`가 이것) 같은
**전체 사이클의 20% 남짓 폭의 좁은 창**이다. 즉 이 프로젝트는 "전체 곡선의 극히
일부만 잘라낸 좁은 창"과 "전체 곡선 그대로"라는, **물리적 폭이 5배 이상 차이나는
두 종류의 입력**을 **동일한 `RawCNN` 아키텍처**(동일 `k=7`, 동일 2-stage
downsample, 동일 `RAW_N=48`)에 그대로 통과시킨다. 이게 구조적으로 맞는 선택인지를
`docs/HI_ANALYSIS.md`의 물리적 특성 분석과 `_resample_segment`
(`4_hi_analysis/hi_correlation.py:336`)의 실제 리샘플 규칙에 근거해 짚는다.

### 9.1 커널 수용영역(receptive field)이 "그리드 상대"이지 "물리량 절대"가 아니다

`_resample_segment`는 세그먼트의 원래 포인트 수·물리적 q_frac 폭과 무관하게 **항상
`RAW_N=48`개 그리드로 선형보간**한다(346행 `grid = np.linspace(0,1,RAW_N)`). 이건
"세그먼트마다 다른 길이를 CNN이 처리할 수 있는 고정 크기로 맞춘다"는 목적에는
필수지만, 그 대가로 **stem의 `k=7` 커널이 실제로 훑는 물리적 q_frac 폭이 세그먼트
폭에 비례해서 달라진다**:

- `full_cycle`(폭 1.0, 방향당 전체 곡선): `k=7`은 전체 사이클의 `7/48 ≈ 14.6%`에
  해당하는 q_frac 구간을 한 번에 본다.
- `q_frac_wide`(`n2=0.2`, 세그먼트 폭 0.2): 같은 `k=7`이 이번엔 세그먼트 자체
  폭(0.2)의 `7/48 ≈ 14.6%` — 즉 **전체 사이클 기준으로는 `0.2 × 14.6% ≈ 2.9%`**밖에
  안 되는 훨씬 좁은 구간만 훑는다.

**즉 "국소적인가 광역적인가"의 의미 자체가 어느 축에서 학습됐는지에 따라 5배
달라진다.** `full_cycle`에서 stem이 잡아내는 "국소 패턴"은 사실 사이클 전체
스케일에서 보면 상당히 광역적인 변화(예: 방전 전체 진행에 걸친 완만한 하강)이고,
`q_frac_wide`에서 같은 커널이 잡아내는 "국소 패턴"은 진짜로 좁은 창 안의 미세
변화(knee, plateau 기울기)다. `MODEL_SPECS.md` §4.1의 설계 근거("플래토 진입/이탈
기울기, knee point 포착")는 후자(좁은 세그먼트) 상황을 염두에 둔 설명에 가깝다 —
`full_cycle`처럼 세그먼트 폭 자체가 이미 knee point 여러 개(전체 충/방전 사이클에는
plateau 진입부·중심·이탈부가 모두 한 세그먼트 안에 다 들어있음)를 포함하는 경우,
`k=7` stem이 그 각각을 분리해서 포착하기엔 상대적으로 너무 좁은 시야일 수 있다 —
이 지점은 이번 세션에서 실측하지 않은 가설이다.

### 9.2 좁은 세그먼트일수록 "CC 정전류 = `|I|` 채널 정보량 0"의 비중이 커진다

`HI_ANALYSIS.md`가 반복해서 지적하는 물리적 사실: **CC(정전류) 구간에서 `|I|`는
상수**다(S06/S07 "CC 방전 전 구간: 전류 I = 상수 → 열화와 무관 → 신호 완전 없음").
`c_hi`(CC→CV 전환 포함) 구간을 제외하면 `raw_i` 채널은 세그먼트 전체에서 **거의
평평한 직선**이다. `RawCNN`은 입력 2채널(V, |I|)에 동일한 conv 필터를 적용하므로,
`c_hi`가 아닌 대부분의 세그먼트에서 **입력 채널의 절반이 사실상 상수 오프셋
정보(그 세그먼트의 설정 C-rate 값) 하나만 나른다** — CNN이 그 채널에서 학습할
"모양"(shape)이 거의 없다는 뜻이다. 세그먼트가 좁을수록(`q_frac_wide`/`vqslope`처럼)
CC 구간에 완전히 포함될 확률이 높아 이 문제가 더 두드러지고, `full_cycle`처럼 넓은
세그먼트는 자체적으로 CC→CV 전환을 포함할 가능성이 높아(방전은 보통 CC-only라
예외지만 충전은 `full_cycle`이 CC+CV를 모두 포함) 상대적으로 `|I|` 채널에 실제
모양 정보가 있다. **다시 말해 `|I|` 채널의 유효 정보량도 축·세그먼트 폭에 따라
구조적으로 달라진다** — 이 역시 `RawCNN`이 모든 축에 대해 동일하게 취급하는 지점.

### 9.3 좁은 세그먼트(plateau 중심)는 "거의 평평한 직선 + 미세 잡음"에 가깝다

`HI_ANALYSIS.md` S01/S13/L02/L03/L07 등이 공통으로 지적하는 점: LFP는 상전이 반응이
극도로 평탄한 OCV를 가져(`dOCV/dSoC ≈ 0`), 플래토 중심 세그먼트(`dis_mid`/`c_mid`)의
V 곡선은 **건강한 셀 기준 변동 폭이 수 mV 수준**이다("플래토에서 V가 거의
상수(std ≈ 0~5 mV)", L03). `q_frac_wide`의 `dis_mid`/`c_mid`처럼 세그먼트가 온전히
플래토 내부에 위치하면, CNN에 들어가는 48포인트 `raw_v` 곡선은 **사실상 완만한 단조
직선에 가깝고, "국소 특징"이라 부를 만한 게 knee point 자체가 아니라 그 직선의
아주 미세한 기울기·곡률뿐**이다 — `MODEL_SPECS.md`가 "국소 특징(knee point)이 SOH에
민감"이라고 든 근거는 사실 **전환 구간을 포함하는 세그먼트(`dis_hi`/`dis_lo`/`c_lo`/
`c_hi`)에 훨씬 더 강하게 적용되는 논리**이고, 순수 plateau 세그먼트에서는 오히려
"직선에 가까운 곡선에서 아주 작은 왜곡을 잡아내는" 훨씬 어려운 문제에 가깝다.
`ResBlock`의 잔차 구조(§2)는 "입력에 작은 보정값을 더한다"는 점에서 이 미세 왜곡
포착에 적합할 수 있지만, `MaxPool1d(2)`(stem)와 `stride=2` conv(downsample)로 48→12로
정보를 압축하는 과정에서 원래도 수 mV 수준인 미세 신호가 잡음과 함께 더 뭉개질
위험이 있다 — 이건 어느 방향이 우세한지 이 프로젝트에서 검증된 바 없는 가설이다.

### 9.4 경계 절단(cut boundary) 자체가 인위적 "가짜 knee"를 만들 수 있다

세그먼트 경계(`q_frac_lo`/`q_frac_hi`)는 물리적 전환점이 아니라 **축 설정이 정한
임의의 q_frac 값**이다(`q_frac_wide`의 `zone`/`n1`/`n2`, `vqslope`/`q_abs`의 각자
기준). 즉 `dis_mid` 세그먼트의 시작·끝점은 "여기서 플래토가 시작/끝난다"는 물리적
근거가 아니라 "설정값이 여기로 잘랐다"는 인위적 경계다. `Conv1d(..., pad=3)`의
zero-padding은 신호가 경계에서 0으로 꺾인다고 암묵적으로 가정하는데, 실제로는
세그먼트 양 끝에서 V/I가 0이 아니라 임의의 값에서 잘려나간 것이므로, **stem의 첫
conv가 세그먼트 양 끝 근처에서 "실재하지 않는 가짜 기울기"를 만들어낼 위험**이
있다(zero-padding과 실제 신호 값 사이의 인위적 불연속). 이 문제는 세그먼트가
좁을수록(전체 48포인트 중 padding 영향을 받는 앞뒤 몇 포인트의 비중이 커짐) 더
크게 작용한다 — `full_cycle`은 세그먼트 경계가 실제 방향 전환점(방전 시작/끝)과
일치해 상대적으로 이 문제에서 자유롭지만, `q_frac_wide`류 좁은 세그먼트는 이
경계효과에 더 취약하다. 이 역시 실측 검증(예: padding 방식을 `zeros`에서
`replicate`로 바꿔 비교)은 이뤄진 바 없다.

### 9.5 종합 판단

| 축 | 세그먼트 폭 | stem 유효 물리폭 | `\|I\|` 정보량 | plateau-only 위험 | 경계효과 위험 |
|---|---|---|---|---|---|
| `full_cycle` | 1.0(전체) | ~14.6% (넓음) | 있음(CC+CV 혼재) | 낮음(knee 여러 개 포함) | 낮음(경계=실제 방향전환) |
| `q_frac_wide`(`n2=0.2`) | 0.2 | ~2.9%(좁음) | 구간별로 없거나(`c_hi` 외) | 높음(`dis_mid`/`c_mid`가 특히) | 높음(임의 절단) |

결론적으로, 지금의 `RawCNN`(고정 `k=7`, 고정 2-stage downsample, 고정 `RAW_N=48`)은
**"세그먼트 폭이 얼마든 동일하게 처리한다"는 단순함의 대가로, 축마다 실제로는
서로 다른 신호 특성(수용영역의 물리적 의미, `|I|` 채널 정보량, plateau-직선 근접도,
경계효과 민감도)을 하나의 구조로 뭉뚱그린다.** 이게 실제로 성능에 얼마나
해로운지는 이 문서의 §6/§8과 마찬가지로 미검증 가설이지만, 방향성 있는 개선안을
들자면:

- **커널 크기를 세그먼트 폭(`zone`/축 설정)에 비례해 조정**(예: `q_frac_wide`처럼
  좁은 축은 더 작은 `k`, `full_cycle`처럼 넓은 축은 더 큰 `k`) — 물리적 수용영역을
  축 간에 맞추는 방향.
- **`|I|` 채널이 거의 상수인 세그먼트(`c_hi` 외)에 대해서는 CNN을 `V` 단일 채널로
  단순화**하거나, 반대로 `|I|`의 절대 레벨(그 세그먼트의 C-rate)만 별도 스칼라로
  넘기고 conv는 `V`에만 적용하는 대안도 고려 가능.
- **zero-padding 대신 `replicate`/`reflect` padding**으로 경계효과를 완화 — 특히
  좁은 세그먼트 축에서 시도해볼 만한 저비용 변경.

이 세 가지 모두 이번 세션에서 구현·검증한 것은 아니며, 이 절 전체가 이 문서의
다른 절들과 마찬가지로 **코드/문서 근거는 확인됐으나 어블레이션으로 검증되지
않은 가설**이라는 점을 다시 한번 밝혀둔다.

## 10. 신규 요구사항 기반 재설계 — 부호 있는 전류, MIT/HUST 특성, 3차원 출력 병목

다음 세 요구사항을 만족하는 새 `RawCNN` 구조를 설계한다:

1. CNN 입력의 전류 채널을 `|I|`(절댓값)이 아니라 **부호 있는 `I`**로 바꾼다.
2. MIT/HUST 데이터 특성을 근거로 지금 구조가 적절한지 평가하고 세부 구조를 제안한다.
3. CNN 출력 차원을 **3개**로 줄이고, 각 차원에 **(1) 시나리오별 특징, (2) 충/방전
   강도별 특징, (3) SOH 최대 연관 특징**이라는 서로 다른 의미를 명시적으로 부여한다.

이 절은 코드 변경을 아직 실행하지 않은 **설계 문서**다 — 근거는 실제 코드/데이터
문서에서 확인된 사실이고, 구조 자체는 이번 세션에서 제안만 하고 구현·학습·검증은
하지 않았다.

### 10.1 요구사항 1 — 부호 있는 전류 입력

**현재 abs()가 적용되는 위치**: `4_hi_analysis/hi_correlation.py`에서 세그먼터에
넘기는 전류는 방전(1908/1911행)·충전(1974행) 모두 `i_mag = np.abs(i)` /
`ic = np.abs(chg_grp["current_A"]...)`로 **부호가 이미 제거된 뒤** 전달된다.
`_resample_segment`(336행)는 이 절댓값을 그대로 받아 `raw_i_{seg}` 컬럼에 저장하므로
(1961-1963행, 2026-2028행), 지금 CNN이 보는 `raw_i`는 시작부터 끝까지 항상 `≥0`이다.

**패치가 이렇게 간단할 수 있는 이유**: 원본 스키마 자체가 이미 부호를 규정해 두고
있다 — `docs/DATASET_HUST_README.md`: `"current_A: 양수=충전, 음수=방전
(MIT·HUST 동일)"`. 그리고 세그먼트 레코드에도 이미 이 부호와 정확히 일치하는
필드가 있다 — `common/scenario/base.py:37`, `SegmentRecord.direction: int  # +1=충전 /
-1=방전`. 즉 **세그먼트 하나 안에서는 방향이 절대 안 바뀌므로(각 세그먼트는 충전
아니면 방전 한쪽에만 속함), 부호는 샘플별로 새로 구할 필요 없이 이미 알고 있는
`direction` 스칼라 하나를 곱하기만 하면 복원된다**:

```python
# hi_correlation.py:1961-1963 / 2026-2028 두 지점 모두 동일 패치
_rv, _ri = _resample_segment(vs_s, ims_s, qcs_s)     # 기존과 동일(절댓값 기준 보간)
_sign = 1.0 if _rec.direction > 0 else -1.0
row[f"raw_v_{seg}"] = _rv.tolist()
row[f"raw_i_{seg}"] = (_ri * _sign).tolist()          # 부호만 사후 적용
```

**주의**: HI 통계 함수들(`_seg_stat`/`_seg_diff`/`_seg_lfp`, 예: `i_std`,
`corr_qi`, `q_cum = cumsum(i_mag·dt)`)은 여전히 **절댓값 기준 `ims_s`를 그대로
써야 한다** — `q_cum`이 누적 전하량인 이상 부호를 넣으면 음수로 발산해 의미가
깨진다. 부호는 **CNN에 들어가는 `raw_i` 컬럼에만** 적용하는 것이 맞고, 이 두
용도(HI용 절댓값 vs CNN용 부호)를 같은 변수로 섞으면 안 된다.

**부호 도입의 실질적 효과**: 지금 `direction`은 이미 `scr_model.py:317`
(`feat_parts += [direction.unsqueeze(1), ...]`)에서 회귀 헤드에 별도 스칼라로
명시적으로 들어간다. 그런데 CNN 입력의 `raw_i`가 항상 `≥0`이면, **CNN 내부
conv 필터 입장에서는 충전 세그먼트와 방전 세그먼트의 전류 채널이 "같은 종류의
곡선"으로 보인다**(둘 다 양수 곡선, 모양의 차이만 있음) — 부호를 살리면 전류
채널 자체가 방향을 명시적으로 나르게 되어, `V` 채널과 `I` 채널의 **동反위상 여부**
(방전: V↓ 동안 I<0 유지, 충전: V↑ 동안 I>0 유지 — §1 L01 "V=OCV∓I·R_int" 원리)를
conv가 더 직접적으로 학습할 수 있는 신호로 바뀐다. 이건 요구사항 3-1(시나리오별
특징)의 재료로 직접 연결된다 — 아래 §10.3 참고.

### 10.2 요구사항 2 — MIT/HUST 데이터 특성에 비춘 구조 평가

`docs/DATASET_HUST_README.md`에서 확인한 두 데이터셋의 충전 프로토콜 공통점·차이점:

| 항목 | MIT | HUST |
|---|---|---|
| 충전 구조 | **2단계**: fast CC → 1C CC → CV | **2단계**: fast CC → 1C CC → CV (동일 구조) |
| fast CC C-rate | **3.3~5.5C, 셀마다 다름** | **5.5C, 전 셀 균일** |
| fast→1C 전환 SOC 타겟 | ~80% SOC | ~72% SOC(q_frac≈0.72, 고정) |
| 말기 CV 시작 q_frac(열화 후) | 0.51~0.97(셀 편차 큼) | 0.68~0.87(범위 좁음, 균일 하락 패턴) |
| 방전 | 1C CC 단일단, 2.75V 컷오프 | 1C CC 단일단, 2.75V 컷오프(동일) |
| 온도 | 가변(문서 미명시) | 30.0°C 고정(항온조) |

**평가 1 — 두 데이터셋 모두 충전 구간에 "진짜 계단형 불연속"이 있다.** `|I|`(또는
부호 있는 `I`)가 fast-CC 구간(MIT 3.3~5.5C / HUST 5.5C)에서 1C CC로 전환되는
순간 **전류가 즉시 5~30% 수준으로 뚝 떨어지는 계단(step)**이 생긴다 — 지금까지
`MODEL_SPECS.md` §4.1이 근거로 든 "knee point"(전압 곡선의 완만한 곡률 변화)와는
성격이 다른, **훨씬 날카로운 불연속**이다. §9.2에서 지적한 "CC 구간은 `|I|`가
상수라 정보가 없다"는 결론은 **`chg_lo`/`chg_mid` 경계 부근을 포함하는 세그먼트에는
그대로 적용되지 않는다** — 그 경계가 세그먼트 안에 들어오면 `|I|` 채널에 뚜렷한
계단 신호가 생기기 때문이다.

**평가 2 — 그 계단의 "위치"(q_frac)가 열화의 직접적 지표다.** HUST 문서가
명시적으로 보여주는 사실: 초기엔 `1C CC 구간`이 총 용량의 ~24%를 추가로 충전한
뒤에야 CV가 시작되지만(`cv_qfrac≈0.96`), 저항 급증 이후엔 1C CC 진입 직후 바로
3.6V 컷오프에 도달해 `cv_qfrac`이 **0.96→0.70대로 급락**한다 — 즉 "CC→CV 전환이
언제(q_frac 몇 지점에서) 일어나는가"가 R↑ 열화를 사이클 수십~수백 단위의 급격한
전환으로 드러내는 신호다. **이건 지금 구조의 다운샘플링 방식과 정면으로 부딪힌다**
— 현재 `RawCNN`은 `stem`(48→24, MaxPool)과 `downsample`(24→12, stride=2 conv)로
**두 번** 해상도를 줄인 뒤 `AttentionPool`을 적용한다. 결과적으로 `AttentionPool`이
보는 12개 위치 각각은 원본 48그리드의 4개 포인트를 뭉친 것이라, 세그먼트 폭
20%(q_frac_wide 기준, §9.1)의 `chg_hi` 안에서 전환점이 이동하는 범위가 세그먼트
폭의 상당 부분을 차지한다면 이 위치 이동을 12단계로만 구분해야 한다 — 위치
민감도가 이 데이터셋의 핵심 열화 신호인데 구조는 그 위치 해상도를 적극적으로
버리고 있는 셈이다.

**평가 3 — MIT의 fast-CC 세기 자체가 셀마다 다르다는 것은 "세기" 축과 "SOH" 축을
분리해야 할 이유를 강화한다.** HUST는 fast-CC가 5.5C로 전 셀 균일해 전류 레벨
자체가 셀 식별 정보를 거의 담지 않지만, MIT는 3.3~5.5C로 셀마다 고정 배정돼 있어
**전류 레벨의 절대값이 그 자체로 "이 세그먼트가 어느 셀 프로토콜에 속하는가"라는,
SOH와 무관한 정보를 나른다.** 만약 CNN 출력이 지금처럼 단일 뭉뚱그려진 64D라면
이 프로토콜 신호가 아무 견제 없이 SOH 관련 표현과 섞일 수 있다 — 요구사항 3에서
"세기" 전용 차원을 따로 두라는 요청은 바로 이 문제(프로토콜 세기 신호와 SOH 신호의
얽힘)를 구조적으로 분리하자는 것과 정확히 부합한다.

**평가 4 — 방전은 두 데이터셋 모두 여전히 단일 CC라 §9.2/§9.3의 결론이 유지된다.**
방전 세그먼트(`dis_hi/mid/lo`)에는 계단형 불연속이 없다(1C CC 단일단, 2.75V
컷오프로 MIT·HUST 동일) — §9.3에서 지적한 "plateau 세그먼트는 거의 평평한 직선"
문제는 방전 쪽에서는 그대로 남아있다. **즉 이번 재설계로 얻는 이득(계단 위치
해상도)은 충전 세그먼트에 집중되고, 방전 세그먼트에는 원래 구조 대비 이득이
제한적이다** — 방전에서는 오히려 §9.3이 지적한 "미세 신호가 다운샘플에 뭉개질
위험"이 더 지배적인 고려사항으로 남는다.

**구조 제안**: 위 근거를 종합해 다음 변경을 제안한다.

- **다운샘플을 2단계 → 1단계로 축소**: `stem`의 `MaxPool1d(2)`(48→24)만 남기고,
  기존 `downsample`(`Conv1d(32→64,k=3,stride=2)`, 24→12)을 **공간 축소 없는 채널
  확장**(`Conv1d(32→64,k=1,stride=1)→BN→GELU`, 24→24)으로 바꾼다. `ResBlock2`는
  채널 64·길이 24에서 그대로 동작한다. `AttentionPool`이 보는 위치 수가 12→24로
  늘어 CC→CV 전환점 위치를 2배 세밀하게 구분할 수 있다. 대가는 `ResBlock2`가
  처리하는 시퀀스 길이가 2배로 늘어 그 구간의 연산량(FLOPs)이 대략 2배가 된다는
  것 — 파라미터 수 자체는 오히려 줄어든다(§10.5 표 참고, `k=1` 채널확장 conv가
  기존 `k=3,stride=2` conv보다 파라미터가 적음).
- **stem의 `k=7`은 유지**: 계단형 전환의 "가장자리"를 안정적으로 검출하려면
  최소 2~3포인트 폭의 커널로는 잡음에 취약하다 — `k=7`(48그리드 기준 ~14.6%)은
  이 계단을 몇 개 위치에 걸쳐 완만하게 스미어링하되 잡음엔 강인한, 적절한
  절충으로 판단해 변경하지 않는다. 이 폭이 `full_cycle`처럼 넓은 축에서
  상대적으로 좁아진다는 §9.1 지적은 여전히 유효하지만, 그건 이번 세 가지
  요구사항과 직접 관련이 없어 이 설계에서는 다루지 않는다.
- **온도 정보(HUST 고정 30°C vs MIT 가변)는 이 설계의 범위 밖**이다 — `RAW_CH=2`
  (V, I)에 온도 채널이 없다는 것은 §7의 t 채널 논의와 마찬가지로 별도 검토
  대상이지, 지금 구조 변경으로 해결되는 문제가 아니다.

### 10.3 요구사항 3 — 3차원 출력 병목 설계

**"출력 차원을 3으로 줄인다"는 선언만으로는 의미가 생기지 않는다.** 지금처럼
`Linear(64,64)` 하나로 압축해봐야, 그 3개(또는 64개) 숫자가 "시나리오 정보"인지
"세기 정보"인지 "SOH 정보"인지는 **그 숫자가 어떤 손실 함수로 학습됐는지**에 의해
결정된다 — 차원 수를 줄이는 것 자체는 의미 부여와 무관하다. 따라서 이 설계는 **3개
스칼라 각각에 별도의 지도(supervision) 신호를 명시적으로 연결**하는 구조를
제안한다.

```
trunk (공통, §10.2 적용됨):
  stem → ResBlock1(32,len24) → chan_expand(32→64,k1,len24) → ResBlock2(64,len24)
  → (B, 64, 24)

3개의 독립된 AttentionPool 분기 (핵심 — 서로 다른 위치에 주목 가능해야 세 성격이
실제로 분리된다):
  pool_scen : AttentionPool1d(64) → (B,64) → Linear(64,1) → h_scen      (B,1)
  pool_int  : AttentionPool1d(64) → (B,64) → Linear(64,1) → h_intensity(B,1)
  pool_soh  : AttentionPool1d(64) → (B,64) → Linear(64,1) → h_soh       (B,1)

cnn_emb = concat([h_scen, h_intensity, h_soh], dim=1)   # (B, 3)
```

**왜 풀링 자체를 3개 분리해야 하는가**: 공유 풀링 하나에 `Linear(64→3)`만
얹으면, 세 출력이 "같은 위치 가중치로 본 같은 표현의 세 가지 선형 투영"에 불과해
분리가 약하다. 반면 분기마다 **별도 `score = Linear(64,1)`**을 두면(파라미터
`3×65=195`, 무시할 수준), 예컨대 `pool_int`는 §10.2가 밝힌 전류 계단 근처 위치에,
`pool_soh`는 knee/plateau 부근 위치에, `pool_scen`은 세그먼트 전체 모양에 각각
독립적으로 주목하도록 **학습을 통해 서로 다른 attention 분포에 도달할 여지**가
생긴다. (이 분리가 실제로 일어나는지는 학습 후 세 개의 `score` 가중치를
비교해봐야 확인 가능 — §3에서 이미 지적했듯 이번 세션은 그 시각화까지는 하지
않는다.)

**각 차원의 지도 신호(가장 중요한 설계 결정)**:

| 차원 | 의미 | 지도 신호 | 손실 | 비고 |
|---|---|---|---|---|
| `h_scen` | 시나리오별 특징점 | 이미 알려진 세그먼트 라벨 `scen`(dis_hi/mid/lo, chg_lo/mid/hi) | `Linear(1→n_scen)` 병목 분류기의 CE | 스칼라 1개로 6-way를 구분해야 하는 **정보 병목**을 강제 — 이게 있어야 "1개 숫자가 시나리오를 나른다"는 요구사항 3-1이 실제로 성립 |
| `h_intensity` | 충/방전 세기 | 세그먼트 자신의 raw 데이터에서 바로 계산 가능한 `mean(\|I_seg\|) / cap_ref`(§10.2 평가2/3 근거 — `cap_ref`는 `q_abs` 축의 기존 BOL-anchor 메커니즘 재사용) | MSE(자기지도, self-supervised) | 라벨 없이 입력 자체에서 유도되는 타깃이라 데이터 추가 수집 불필요. HUST에서 이 타깃은 CC→CV 전환 위치와 간접 연동(§10.2 평가2)되므로 완전히 "SOH와 무관"하지는 않으나, 이는 프로토콜의 실제 물리적 반응이지 인위적 라벨 누출이 아님 |
| `h_soh` | SOH 최대 연관 | 기존 `cap_head`의 최종 SOH 회귀 손실 — `feat_parts`에 `h_soh`만 연결(기존 64D `cnn_emb` 대신) | 기존 SOH MSE(Phase 2) | 유일하게 최종 정답 라벨에 직접 연결된 차원 |

**세 손실이 서로를 침범하지 않게 하는 장치 — 상호 비상관(decorrelation) 페널티**:
위 표만으로는 세 스칼라가 실제로 서로 다른 정보를 담는다는 보장이 없다(예:
`h_soh`가 `h_intensity`와 똑같이 학습돼도 SOH MSE는 여전히 줄어들 수 있음, 특히
§10.2 평가2처럼 세기 신호가 SOH와 실제로 상관되는 경우). 배치 단위로 세 벡터
사이의 상관계수를 계산해 페널티를 추가한다:

```python
L_decorr = sum(corr(h_i, h_j) ** 2 for i, j in [(scen,int), (scen,soh), (int,soh)])
L_total  = L_main + λ_int * L_intensity + λ_scen * L_scen_ce + λ_decorr * L_decorr
```

`λ_decorr`는 "완전히 독립"을 강제할 만큼 크게 주면 `h_soh`가 SOH와 무관하게
`h_scen`/`h_intensity`를 피하기만 하는 퇴화가 생길 수 있으므로, 이 값은 실험으로
조정해야 하는 하이퍼파라미터다 — 이번 설계는 항목의 존재와 이유만 제시하고 구체적
값은 제안하지 않는다.

**Phase 구조에 대한 함의 — `train_classifier.py`를 건드려야 한다.** 이전 대화(요약
참고)에서 이미 확인했듯 `train_classifier.py`는 SOH 라벨을 전혀 읽지 않는다("Phase
2의 `cap_head` 가중치는 전혀 읽지 않는다", `REGRESSION_UPGRADE.md` §8.2). 방안2(a)처럼
CNN을 **분류기 단계(Phase 1)에서 미리 학습해 얼리는** 경로를 쓰려면, `h_soh`가
SOH와 연관되도록 학습되려면 **Phase 1 학습 스크립트에 SOH MSE를 위한 보조 프로브
헤드(`Linear(1,1)`, 학습 후 폐기)를 새로 추가**해야 한다 — 그렇지 않으면 (a) 경로의
`h_soh`는 아무 지도 신호도 받지 못한 채 무작위에 가깝게 남는다. 방안2(b)(회귀와
함께 학습)는 이 문제가 없다 — `h_soh`가 자연스럽게 `cap_head`의 그래디언트를
받는다. **즉 이 설계는 (a)/(b) 두 경로에 다른 구현 비용을 요구하며, (a) 쪽이
`train_classifier.py` 수정이라는 추가 작업을 필요로 한다.**

### 10.4 CNN 입력/출력 스케일 정규화

**입력 쪽**: 부호 있는 `I`로 바꿔도(§10.1) `stem`의 기존
`BatchNorm1d(32)`(conv 직후)는 그대로 유효하다 — BN은 채널별 평균을 빼고 분산으로
나누는 연산이라 입력이 `[0, I_max]`(절댓값)이든 `[-I_max, I_max]`(부호 포함)이든
동일하게 그 채널의 평균/분산을 흡수한다. 다만 부호를 살리면 그 채널의 전역 분포가
"충전 세그먼트=양수 덩어리, 방전 세그먼트=음수 덩어리"로 **양봉형(bimodal)에
가까워진다** — 이 자체는 BN 계산에 문제가 없지만(단일 평균·분산으로 정규화하는 게
불가능하지 않음, 최적은 아닐 수 있음), 필요하면 이후 `direction`별로 별도 BN
통계를 두는 조건부 정규화(conditional BatchNorm)로 개선할 여지가 있다 — 이번
설계에서는 필수로 제안하지 않고, 무조건부 `BatchNorm1d(32)` 유지를 기본안으로
한다(단순함 우선, 파라미터 증가 없음).

**출력 쪽 — 이번 재설계에서는 반드시 추가해야 한다.** §4에서 이미 코드로 확인한
사실: 기존 `RawCNN`의 최종 `proj`(`Dropout→Linear→GELU`)는 **출력에 정규화가
전혀 없다** — 방안1(`raw_flat`)이 `nn.BatchNorm1d(RAW_CH*RAW_N)`을 별도로 추가한
것과 대비된다(§4/§8 참고). 64차원일 때는 "64개 중 일부 차원의 스케일이 어긋나도
나머지 다수 차원이 완충한다"는 여지가 있었지만, **3차원으로 줄이면 각 차원이 그
자체로 유일한 정보 채널이라 스케일 불일치가 즉시 최종 성능에 반영된다** — 예컨대
`h_scen`(CE 병목이라 로짓 스케일에 가까움)과 `h_soh`(MSE 회귀라 SOH 잔차 스케일에
가까움)는 자연 학습 과정에서 전혀 다른 수치 범위에 정착할 가능성이 높고, 이 둘을
그대로 `feat_parts`에 concat해 `cap_head`(HI 피처들과 함께 들어가는 선형 입력)에
넣으면 `cap_head`의 첫 선형 레이어가 이 스케일 차이를 흡수하는 가중치를 따로 학습해야
한다 — 학습 초기 수렴을 늦추는 요인이 될 수 있다. **제안**: `concat([h_scen,
h_intensity, h_soh])` 직후에 `nn.BatchNorm1d(3)`을 추가하고, `feat_parts`에는 이
정규화된 3차원을 넣는다. 위 §10.3의 보조 손실(`L_scen_ce`, `L_intensity`)도 이
정규화된 값 위에서 계산해 "공개 출력값(cnn_emb)"과 "손실 계산에 쓰이는 값"을
분리하지 않는다 — 방안1의 `raw_flat_norm`과 동일한 패턴을 그대로 재사용하는
것이라 새로운 설계 개념이 아니다.

배치 크기가 작을 때(`BatchNorm1d(3)`은 채널이 3개뿐이라 배치 내 표본 수가
정규화 안정성에 특히 민감) `LayerNorm` 대체도 고려할 수 있으나, `LayerNorm(3)`은
**세 값 자체가 서로 다른 의미의 스칼라라 "3개 차원에 걸친 정규화"가 의미론적으로
어색하다**(LayerNorm은 같은 샘플 내 채널들이 비교 가능한 스케일이라는 전제를
쓰는데, `h_scen`/`h_intensity`/`h_soh`는 애초에 다른 종류의 양이다) — 따라서
`BatchNorm1d(3)`(각 차원을 배치 축으로 독립적으로 정규화)이 이 3차원 설계에는
더 적합한 선택이다.

### 10.5 파라미터/연산량 개략 비교

| 구성요소 | 기존(§0) | 신규 제안 |
|---|---|---|
| stem | 544 | 544(불변) |
| ResBlock1(32,len24) | 6,336 | 6,336(불변) |
| 채널 확장/다운샘플 | `downsample`(k3,stride2): 6,336 | `chan_expand`(k1,stride1): **2,240**(↓) |
| ResBlock2(64) | len12: 24,960 | len**24**: 24,960(파라미터 동일, **연산량 2배**) |
| 최종 헤드 | `AttentionPool×1`(65) + `proj Linear(64,64)`(4,160) = 4,225 | `AttentionPool×3`(195) + `Linear(64,1)×3`(195) = **390**(↓) |
| 출력 정규화 | 없음 | `BatchNorm1d(3)`: 6(신규, 무시 가능) |
| **합계(파라미터)** | **42,401** | **≈34,476**(약 19% 감소) |
| 출력 차원 | 64 | **3** |

파라미터 수는 오히려 줄지만(최종 헤드가 64D 대신 3D만 생성하면 되므로), `ResBlock2`가
2배 긴 시퀀스를 처리해 그 구간 FLOPs는 약 2배가 된다 — 전체 네트워크가 원래도
42K 파라미터의 경량 모듈이라 이 정도 연산량 증가는 실무적으로 부담이 크지
않다고 판단하나, 실측(예: 배치당 forward 시간)은 하지 않았다.

### 10.6 이 설계가 포기하는 것 — 명시적 트레이드오프

`MODEL_SPECS.md` §4.1의 원래 설계 목표는 "출력 차원을 HI 64D와 동일하게 맞춰
동등한 정보 예산을 준다"였다(§0/§4 참고, `d_out=64`). **이번 3차원 설계는 그
목표를 의도적으로 포기한다** — HI(64D)와 "동등한 용량"을 갖는 범용 임베딩 대신,
**해석 가능하고 역할이 고정된 3개의 저용량 채널**로 대체하는 것이다. 트레이드오프:

- **얻는 것**: 각 차원이 무엇을 나르는지 설계 시점에 알 수 있음(사후 상관분석에
  의존하지 않음), §6/§8이 지적한 "cnn_emb가 정확히 뭘 담고 있는지 불투명하다"는
  문제의 근본적 해소, `avg_cost`류 비용 지표에서 64D→3D로 인한 명확한 비용 절감.
  - 신규 CNN 구조에 대한 신뢰(SOH 예측·시나리오 분류에 각각 실제로 기여하는지)를
    사후 상관관계 분석이 아니라 학습 손실 설계 자체로 보장한다는 게 §6/§8 대비
    가장 큰 방법론적 차이.
- **잃는 것**: 표3(§10.3)로 미리 규정하지 못한, 사전에 상상하지 못한 유용한 신호가
  있었다면 64D 대비 그걸 담을 여유 공간이 사라진다. 특히 `h_soh` 하나(스칼라)로
  SOH 관련 정보를 다 압축해야 한다는 건 (b) 경로(회귀와 함께 학습, 지금 64D를 다
  씀)가 지금까지 보여온 성능(§0.5/§1 상대적 우위)을 유지할 수 있을지 자체가
  불확실하다는 뜻이기도 하다 — 이 설계는 "해석 가능성"과 "표현력"을 명시적으로
  맞바꾸는 결정이며, 그 맞교환이 실제로 성능 손실 없이 가능한지는 구현·학습 전까지
  알 수 없다.

## 10.8 재설계 — `h_scen`/`h_intensity`를 축 전체(클러스터 제외)에 일반화 + CNN 고유 강점 반영

§10.3의 원래 설계는 `h_scen`을 "이미 알려진 `scen` 라벨에 대한 CE 병목"으로,
`h_intensity`를 "`mean(|I|)/cap_ref`"로 정의했다. 이후 검토에서 두 가지 문제가
드러났다:

1. **축마다 시나리오 개수·성격이 다르다.** 실제 코드로 확인한 `n_scenarios`:
   `qfrac`/`q_frac_wide`/`vqslope`/`q_abs`=6(방향 내 순서형), `protocol`=`2×max_steps`
   (순서형), `vwindow`=`2n+1`(전압 오름차순 순서형), `cluster`=가변(`cluster.py`
   — K-means 클러스터 ID, **순서 없음**), `full_cycle`/`test_rs`=2(방향뿐). CE
   병목은 순서형 소수 축(qfrac 계열)에만 맞고, `cluster`(순서 없는 임의 개수)엔
   구조적으로 부적합하며, 2-클래스 축엔 이미 별도로 주어지는 `direction`
   (`scr_model.py:317`)과 중복이다.
2. **`mean(|I|)`는 이미 존재하는 HI(S06/S07 `i_mean`/`i_std`)를 CNN으로 다시
   만드는 것에 불과**해, CNN이 왜 필요한지에 대한 답이 되지 못한다.

**재설계 원칙**: `vqslope`(`common/scenario/vqslope.py:8-13`)가 이미 확립한
반누출 철학 — "존 경계를 누적 위치(q_frac, q_tot 필요)가 아니라 **그 순간의 곡선
형상**으로 정의해야 라벨(SOH)의 함수가 되지 않는다" — 을 그대로 CNN 출력
차원에도 적용한다.

- **`h_scen` → "국소 평탄도"로 재정의.** 지도 신호: 세그먼트 내부 `|dV/dQ|`로 구한
  플래토 유사도(`L01 lfp_plateau_frac`/`D02 dvdq_std`류 — 세그먼트 자체의 Q-bin
  비율만 쓰므로 `q_tot` 불필요, MSE 회귀). 축과 무관하게 항상 계산 가능(어떤
  축으로 잘랐든 세그먼트의 V-Q 곡선 자체는 항상 존재) — `cluster`만 개념적으로
  무관해 자연히 빠진다. `vqslope`는 이 기준(`|dV/dQ|<θ_flat`, `_curves.py:22`
  `THETA_FLAT=0.25`) **그 자체로 존 경계를 정의**하므로 가장 잘 맞고, `vwindow`도
  전압창=플래토 여부가 원리적으로 강하게 연동된다. `q_frac_wide`는 Q-위치 기반이라
  연관이 간접적. **CNN 고유 강점**: `L01`/`D02`/`D12`/`D14`는 `ΔQ→0`인 CV 인접
  구간에서 수치 발산한다고 `HI_ANALYSIS.md`가 반복 명시(`⚠ CV 발산`) — CNN은
  명시적 나눗셈 없이 conv+BN+attention으로 "평탄함"을 학습해, 정확히 그 발산
  구간에서 기존 수기 공식보다 견고한 대체물이 될 잠재력이 있다.
- **`h_intensity` → "국소 전류 레짐 전환"으로 재정의.** 지도 신호: 세그먼트
  내부에서 전류 레짐이 바뀌는지/어디서 바뀌는지(정규화 위치, `protocol.py`의
  `_detect_steps`와 같은 개념을 축 무관하게 재사용). 마찬가지로 `q_tot` 불필요.
  `vqslope`/`vwindow`의 존 경계(플래토 진입·이탈, 전압창)는 실제 CC→CV 전환이
  그 근처에 자주 걸려(경계 자체가 형상 랜드마크라서) 이 타깃과 자연히
  겹치지만, `q_frac_wide`는 순수 Q-위치라 전환이 세그먼트 안에 들어올지가
  우연에 더 좌우된다(§10.2). **CNN 고유 강점**: `D01`/`D03`/`D05`/`D12`/`D14`가
  동일하게 `c_hi ⚠` 발산 표기 — 같은 논리로 CNN이 명시적 미분 없이 전환의
  존재/위치를 학습.

두 타깃 모두 세그먼트 자기 자신의 상대 위치만 쓰고 `q_tot`/절대 Q를 참조하지
않아 `vqslope`의 반누출 원칙과 일치한다. 서로 다른 물리량(형상 평탄도 vs 전류
전환)이라 §10.3의 비상관 페널티도 그대로 유효하다. `h_soh`는 이 재설계로
변경되지 않는다(아래 §10.9에서 별도 검증).

## 10.9 `h_soh`의 반누출 검증

`h_soh`는 `h_scen`/`h_intensity`와 지도 방식이 다르다 — 세그먼트 자체에서
계산한 약지도 타깃이 아니라 **SOH 정답 라벨로 직접 지도**된다. 이게 이 문서
전체가 경계해온 "누출"에 해당하는지 검증한다.

**결론: 해당하지 않는다.** 이 프로젝트에서 지금까지 "누출"이라 부른 것은 항상
**"입력값(x) 자체가 정답(y) 또는 y와 거의 동치인 미래/절대 정보를 이용해 계산된
경우"**였다(`stat_q_abs`, 시프팅 안 한 duration, §7의 t 채널 논의 등). `h_soh`는:

- **순전파 시점엔 오직 `x_raw`(V, I 곡선)만 입력**으로 쓴다 — `capacity_Ah`는
  전혀 관여하지 않는다.
- `capacity_Ah`는 **역전파(손실 계산)에만** 등장한다 — 이는 `cap_head`를 포함해
  이 프레임워크의 모든 학습 파라미터가 이미 하는 일과 동일하다(SOH 라벨로
  그래디언트를 받는 것 자체는 지도학습이지 누출이 아니다).
- 유일하게 검증이 필요했던 실제 리스크는 "Phase 1(`train_classifier.py`)이 지금
  `capacity_Ah`에 접근하는가"였는데, **grep 결과 이 스크립트엔 `capacity_Ah`/
  `cap_init`/`soh` 참조가 전혀 없다(0건)** — 즉 (a) 경로에서 `h_soh`를 지도하려면
  §10.3에서 이미 지적한 대로 Phase 1에 **새 보조 SOH 회귀 프로브 헤드**를
  추가해야 하고, 이때 쓰는 라벨은 Phase 2가 이미 정답으로 쓰는 것과 **완전히
  동일한, 같은 사이클의 `capacity_Ah`**이므로 새로운 누출 경로가 아니다.
- `x_raw` 자체도 이미 §0-§9에서 확인했듯 절대 Q·절대 duration을 담지 않는
  형태(항상 `[0,1]` 정규화 그리드)라, `h_soh`가 이 입력에서 SOH를 지름길로
  읽어낼 물리적 경로가 없다.

## 10.10 t/dt 채널 추가 — 구체적 구현 설계

`docs/REGRESSION_UPGRADE.md` §8.1이 이미 확립한 안전 공식(`t_rel =
(t-t[0])/(t[-1]-t[0])`, Q축과 동일한 좌표계에 보간)을 그대로 재사용한다 — 절대
지속시간이 아니라 세그먼트 내부에서 시프팅+스케일링한 상대값이라 §7이 검증한
"지속시간=SOH 대리 변수" 누출을 피한다.

**변경 지점**:

1. `4_hi_analysis/hi_correlation.py:336` `_resample_segment` — `dts` 인자를
   추가로 받아 `t = cumsum(dts) - dts[0]`, `t_rel = t/t[-1]`을 구하고, **좌표축은
   그대로 `x`(Q 기반)를 써서** `rt = np.interp(grid, x, t_rel)`을 세 번째
   반환값으로 추가한다. `dts_s`/`dtc_s`는 두 호출부에 이미 존재하는 변수라 새
   데이터 소스가 필요 없다.
2. 호출부 두 곳(1961-1963행, 2026-2028행) — `row[f"raw_t_{seg}"] = _rt.tolist()`
   추가.
3. `5_model/utils/hi_schema.py:50` — `RAW_CH = 2` → `RAW_CH = 3`.
4. `5_model/datasets/segment_dataset.py` — 267행 `raw_cols`에 `"raw_t"` 추가,
   `_build_raw_tensor`(350-359행)에서 `rt` 스택 추가(`np.stack([rv, ri, rt],
   axis=1)`). **구 pkl(raw_t 없음) 호환**: 기존 raw_v/raw_i 존재 여부 분기
   로직(353-358행)과 동일하게 없으면 zero 채널 폴백 — 기존 실험 재현성 유지.
5. `5_model/models/raw_cnn.py` — stem `nn.Conv1d(2,32,...)` → `nn.Conv1d(3,32,...)`.
   파라미터 증가 미미(`32×1×7=224`개, BN 불변).

## 10.11 냉정한 재평가 — 세 피처 전부에 시간이 필요한 건 아니다

세 차원에 균등하게 시간 정보를 반영해야 한다고 하면 과장이다. 각각 실제로 새
정보를 얻는지 따로 따져야 한다.

| 차원 | 시간이 새 정보를 주는가 | 근거 |
|---|---|---|
| `h_intensity`(전류 레짐 전환) | **강하게 필요** | CV 구간에서 `I(t)`는 시간에 지수 감쇠하는데 리샘플 그리드는 Q-균등이라, `dQ/dt`가 큰 CV 초반(정보량 많음)은 소수 그리드로 뭉개지고 `dQ/dt≈0`인 CV 말미(정보량 적음)는 그리드가 과할당된다 — `REGRESSION_UPGRADE.md` §8.1이 지적한 "48점 리샘플이 계단 전환을 뭉갤 수 있다"는 우려가 정확히 이 차원의 핵심 임무(전환 위치 검출)와 충돌한다. `t_rel`은 이 왜곡을 보정할 유일한 단서다. |
| `h_scen`(플래토 평탄도) | **한계적** | 플래토 평탄도는 정의상 Q 기준(dV/dQ)이지 시간 기준이 아니다. 순수 플래토 세그먼트(CC 구간)는 전류가 거의 상수라 `dQ/dt≈const` — Q-그리드와 시간-그리드가 거의 선형 비례해 `t_rel`이 `q_frac` 좌표와 정보 차이가 별로 없다(중복에 가까움). CV가 살짝 걸치는 경계 세그먼트에서만 미약하게 도움. |
| `h_soh`(SOH 최대 연관) | **근거 약함, 오히려 중복 위험** | 시간 채널이 줄 수 있는 정보(플래토 내 전압 드리프트 속도, R↑ 관련 시상수)는 **이미 `HI_ANALYSIS.md`의 L19(`dv_dt_plateau`)가 정확히 이 물리량을 측정하고 "R↑의 직접적 측정값에 가장 가까운 HI 중 하나"(`−●` 강신호)로 문서화돼 있다.** L19는 이미 64-HI 벡터로 `cap_head`에 직접 들어간다 — CNN이 `t_rel`로 같은 정보를 다시 뽑는 건 새 신호가 아니라 **기존 안전한 HI의 중복 재발견**일 가능성이 커서, §10.8이 세운 "CNN만의 고유 강점" 기준에 맞지 않는다. |

**결론**: `t_rel` 채널은 공유 trunk(stem)에는 추가하되, 이득은 균등하지 않다 —
`h_intensity`가 진짜 수혜자이고 `h_scen`은 미미하며 `h_soh`는 오히려 회의적으로
봐야 한다. 이 비대칭을 그대로 남겨두는 것이 정직한 평가다.
