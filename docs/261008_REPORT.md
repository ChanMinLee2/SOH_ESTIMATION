## 1. a vs b — 다중공선성 미적용 효과 (어제 보고 내용)

![a vs b 성능 비교](261008_ab_perf.png)

| | oracle RMSE | oracle R² | hard RMSE | hard R² |
|---|---|---|---|---|
| a(기본) | 0.01736 | 0.9379 | 0.01736 | 0.9379 |
| b(다중공선성 미적용) | 0.01622 | 0.9458 | 0.01622 | 0.9458 |

b가 오히려 R² 0.8%p 더 높다 — 다중공선성 제거가 "거의 중복"인 HI까지 하드 배제하면서, 그 HI들이 갖고 있던 잔여 정보(상관 0.95면 ~10% 남음)를 같이 버리는 **예상된 비용**이다(b는 raw HI를 회귀/분류 양쪽 다 배제 없이 그대로 사용, 커널 HI도 synergy global_dedup 이전 더 많은 후보를 사용). 즉 b가 더 좋아 보이는 건 "제대로 안 돌려서 생긴 착시"이고, 공정 비교는 a vs c다.

**(추측)** 또 다른 원인 후보로, b는 legacy interaction.py 판정 기준상 공유(shared_gate) HI가 25/64개로 a/c(정식 판정 기준 13/64개)보다 훨씬 많다(§4 HI 사용 매트릭스 참고). 공유 HI가 많을수록 시나리오별로 게이트가 쪼개지지 않고 하나의 게이트를 전 시나리오가 같이 쓰는 셈이라, 구조적으로 "시나리오 조건화 없이 학습"한 것에 가까워진다. 이 프로젝트의 핵심 발견("순진한 조건화는 샘플 분할로 성능을 해칠 수 있음", §3.3/§6.1 PREWRITE.md)과 같은 방향이라, b의 우위가 다중공선성 미적용뿐 아니라 "공유 HI 비중이 높아 조건화 손해 자체가 적었다"는 요인도 같이 작용했을 가능성이 있다 — 아직 검증 전이라 가설로만 남겨둠.

## 2. a vs c — 정상화 후 비교 (결론: 큰 차이 없음)

![a vs c 성능 비교](261008_ac_perf.png)

| | oracle RMSE | oracle R² | hard RMSE | hard R² |
|---|---|---|---|---|
| a(기본, 분류기 커널 확장 없음) | 0.01736 | 0.9379 | 0.01736 | 0.9379 |
| c(정식, 분류기 커널+다중공선성 확장 적용) | 0.01758 | 0.9363 | 0.01758 | 0.9363 |

차이는 R² 0.16%p, RMSE 0.0002 수준 — 셀별 예측곡선(`compare_runs.py` 산출물, `model_lib/results/comparison/1008_1126/curve_*.png`)도 육안으로 거의 구분이 안 된다. **분류기에 커널 HI+다중공선성 제거를 추가해도 회귀 성능에는 사실상 영향이 없다.**

### 왜 영향이 없는가 — HI 사용 매트릭스로 본 이유

![c의 커널 HI 사용 매트릭스](261008_hi_kernel_c.png)

`9_eval/plot_hi_usage_matrix.py --run-dir <run>`으로 뽑은 커널 HI 매트릭스(회귀 vs 분류)를 보면, 분류기는 전체 58개 커널 HI 후보 중 **단 2개**(`kernel_chg_mid_g2`, `kernel_dis_mid_g6`)만 켜고 나머지는 전부 끈다. b에서도 똑같은 2개만 켜져 있어 재현성도 확인됨. 분류 자체가 이미 거의 포화(val_cls_acc≈1.0)라 L0 게이트가 대부분을 불필요하다고 판단한 것 — 그러니 이 확장이 모델 전체(특히 회귀) 성능을 크게 바꿀 이유가 애초에 적다.

raw HI 쪽도 참고로 같이 보면(선택 개수, gate_prob≥0.5 / 64):

| | 회귀(시나리오 평균) | 분류(방향 평균) |
|---|---|---|
| a | ~14.5 | ~17.5 |
| b(다중공선성 미적용) | ~20.2 | ~21.5 |
| c | ~14.7 | ~16 |

a와 c는 raw HI 사용량도 거의 동일 수준(다중공선성 제거가 양쪽 다 적용된 결과) — b만 확연히 많다.

## 3. 결론

1. b는 설정 버그(Step5~7 미실행 → legacy fallback)로 다중공선성 제거가 아예 빠진 케이스라 a/c와 직접 비교 대상이 아니다.
2. 공정 비교인 a vs c는 "분류기 커널+다중공선성 확장"의 순수 효과를 보여주며, **회귀 성능 차이는 거의 없다**(0.16%p).
3. 원인은 분류기가 새로 받은 커널 HI 후보 중 2/58만 실제로 쓰기 때문 — 확장 자체는 구조적으로 안전하게 들어갔고, 부작용 없이 "쓸모없는 건 알아서 끄는" 설계 의도대로 작동 중.
4. (향후 검증) `lambda_l0`를 낮춰 분류기가 커널 HI를 더 적극적으로 쓰도록 유도해보고, 그래도 성능 변화가 없는 수준이면 분류기 쪽 커널 HI+다중공선성 확장은 롤백한다 — 효과가 없는 걸 람다 하나로 확인했는데도 복잡도만 남겨둘 이유가 없음.
