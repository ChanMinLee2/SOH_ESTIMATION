# Phase1 HI 랭킹 안정성 개선 — 수정 전 vs v0 vs v1 vs v2 정리

Phase1-2 통합에 앞서, Phase1의 "시나리오별 HI 랭킹이 seed마다 크게 달라진다"는 문제를
고치기 위해 진행한 수정들을 시간순으로 정리한다. 상세 실행 결과/원자료는
`docs/260819_RESULTS.md`(Stage0~6 검증)와 `docs/260820_RESULTS.md`(그룹화/커널 융합
v0/v1/v2)에 있고, 이 문서는 "지금까지 뭘 왜 어떻게 바꿨는지"를 한 번에 훑어보기 위한
요약이다.

## 배경 — 문제와 측정 지표

같은 데이터·같은 하이퍼파라미터로 학습해도 Phase1이 뽑는 시나리오별 HI 랭킹이 seed(초기화/
학습 노이즈)에 따라 크게 흔들려서, 랭킹 자체를 신뢰하기 어렵다. 두 지표로 이를 정량화한다:

- **포화도(saturation)**: `((gate_prob > 0.1) & (gate_prob < 0.9)).mean()` — 게이트가
  "쓴다/안 쓴다"를 아직 확실히 못 정한 비율. 낮을수록 결정이 또렷함.
- **유사도(Kendall τ, Jaccard)**: 서로 다른 seed의 랭킹이 얼마나 일치하는지. τ는 -1~1(1이
  완전 일치), Jaccard는 top-k 집합이 얼마나 겹치는지(0~1). 대략 τ≥0.5, Jaccard≥0.7이면
  "신뢰 가능"으로 본다(자세한 기준표는 `docs/260819_RESULTS.md` 서두 참고).

## 전체 계보

```
Stage0(수정 전, val_rmse 체크포인트)
   -> Stage1+2(포화도 체크포인트 + β 어닐링) = 이후 v0/v1/v2의 공통 "baseline"
        -> v0: 게이트 레벨 그룹화(GroupedHardConcreteGate)
        -> v1: 커널 융합, raw HI 대체 (폐기 — 성능 악화로 v2로 재설계)
        -> v2: 커널 융합, raw HI 유지 + 커널 HI 추가 (설계/구현 완료, 실행 대기)
```

Stage3(다중시드 앙상블)/Stage4(상관 클러스터링 재해석)/Stage5(HI 조합 시너지 스크리닝)는
Stage1+2와 v0 사이의 진단 단계로, `build_synergy_groups.py`(v0/v1/v2가 공유하는 그룹 산출)
로직의 근거가 됐다 — 상세는 `docs/260819_RESULTS.md` 참고.

## 수정 전 — Stage0 (val_rmse 체크포인트)

**로직**: `train_scr.py`의 원래 Phase1. `HardConcreteGate`를 시나리오별/probe별로 독립
학습하고, val_rmse가 가장 낮은 epoch을 체크포인트로 저장.

**특징(5 seed 평균, [0,7,42,123,2024])**:
- Kendall τ(전체 64개 랭킹 기준) = **0.0685** — 사실상 무작위에 가까움.
- 포화도 = **0.1637**(16.4%) — seed별로 1.6%~38%까지 널뜀(20배 차).
- top-k 교집합 기준 τ는 이미 0.5~0.9대("강함")로 나옴 — 불안정성의 상당 부분은 하위권
  (top-k 밖, 실제로 안 쓰이는 HI)의 순서 뒤바뀜 때문.

**원인**: L0 페널티가 아직 다 안 걸린 초반 epoch(≤50)에서 val_rmse가 우연히 최저인 경우가
많아, 게이트가 결정을 안 내린(포화도 높은) 상태의 epoch이 체크포인트로 뽑힘.

## 1차 개선 — Stage1+2 (이후 문서에서 "baseline")

**로직**: 새 트레이너 `phase1_trainer_v2.py`.
1. 체크포인트 선택 기준을 val_rmse → **포화도 최소**로 변경(L0가 완전히 걸린 epoch≥150
   구간에서만).
2. **β(HardConcreteGate 온도) 어닐링**: L0 페널티가 강해지는 epoch 50→150 구간과 같은
   타이밍으로 β를 2/3→0.1로 선형 감소 — 게이트 확률분포를 점점 더 계단함수에 가깝게 만들어
   "확실한 결정"을 유도.

**특징(5 seed 평균)**:
- Kendall τ(전체) = **0.1188** — Stage0 대비 개선됐지만 여전히 "불안정"(0.5 미만) 판정.
- 포화도 = **0.00312**(0.3%) — Stage0 대비 **평균 98% 감소**, seed 간 편차도 사라짐
  (0.2~0.4%대로 일관).
- top-k 교집합 τ는 0.68~0.76("강함")까지 개선.

**seed=42 단일 run(이후 v0/v1/v2 비교의 "baseline")**: `gate_saturation=0.00391`,
`val_rmse=0.01951`, `val_r2=0.9194`, 시나리오당 실제 활성(gate_prob>0.5) HI **2~6개**
(scen_k=25 목표에 한참 못 미침 — 아래 "알려진 한계" 참고).

**남은 한계**: 전체-랭킹 τ가 0.12까지 밖에 안 올라와 여전히 구조적 불안정성이 남음 —
Stage3(앙상블)이 사실상 최종 방어선 역할. Stage4로 "동급 HI끼리 자리만 바뀐 무해한 불안정"과
"진짜 불안정"을 분리해봐도(gap 평균 +0.036) 일부 시나리오(chg_mid/chg_hi)는 여전히 설명이
안 되는 진짜 불안정성이 남음 — 이게 Stage5(HI 조합 시너지 스크리닝)와 v0/v1/v2로 이어지는
이유.

## v0 — 게이트 레벨 그룹화 (`GroupedHardConcreteGate`)

커밋 `1c7bb2d`. **raw HI는 안 건드리고, 게이트 파라미터(`log_alpha`)만 그룹 단위로 묶는다.**

**로직**:
1. `build_synergy_groups.py`(시나리오별 독립): SOH와 단순 상관 큰 HI부터 시드로 삼고,
   ① 다중공선성 배제(그룹 멤버와 원시 상관 `|r|≥0.9`인 후보 제외) → ② 저비용 사전필터
   (상관 상위 M개) → ③ 편상관계수(그룹 전체로 OLS 회귀한 잔차끼리 상관) 최댓값 채택,
   최대 4개까지 그룹 성장. 시너지 파트너 없는 HI는 크기 1 그룹으로 남음.
2. `GroupedHardConcreteGate`(신규 클래스, `hard_concrete.py`): `log_alpha[i] =
   log_alpha_group[그룹] + log_alpha_member[i]`로 파라미터를 그룹 레벨/멤버 레벨 2단 분리.
   다중공선성 있는 HI끼리 그래디언트가 거의 같아 게이트가 랜덤하게 흔들리던 문제를, "그룹을
   켤지" 결정을 그룹 레벨 파라미터로 모아서 완화.
3. `scr_model.py`의 `scen_gates`가 시나리오별로 그룹 있는 곳만 `GroupedHardConcreteGate`,
   없으면 기존 `HardConcreteGate` — `--synergy-groups-json` 미지정 시 완전히 기존과 동일.

**특징(seed=42, baseline과 비교)**:
- `gate_saturation` **0.0**(완전 이산화) — baseline(0.00391)보다도 개선.
- `val_rmse` **0.02076**, `val_r2` **0.9088** — baseline과 거의 동일(소폭 악화).
- top-25 HI Jaccard(vs baseline) **0.43~0.52** — 랭킹이 상당 부분 겹치되 일부 재배치.
- 활성(gate_prob>0.5) HI 개수 시나리오당 **1~3개** — baseline(2~6개)보다도 더 적음(아래
  "알려진 한계" 참고).

**평가**: 3개 변형(v0/v1/v2) 중 "성능 유지 + 포화도 개선"이라는 목표에 1개 seed 기준
가장 근접. 다만 활성 개수가 극도로 적어 "과도한 가지치기"일 가능성은 별도 확인 필요.

## v1 — 커널 융합, raw HI 대체 (폐기 — v2로 재설계됨)

**로직**: `build_synergy_groups.py` 그룹(크기 2+) 멤버 HI들 → SOH를 RBF 커널(Nystroem 근사
+ Ridge)로 fit, 그 예측값을 그룹의 "새 HI"로 삼아 **기존 `x_hi`의 64개 슬롯을 그 값으로
덮어씀**(대체). 시나리오 전체를 합쳐 2차 다중공선성 배제 후 시나리오별 쿼터로 N_HI개를 채움.

**특징(seed=42)**:
- `gate_saturation` **0.02539** — baseline 대비 약 6.5배 악화.
- `val_rmse` **0.04474**, `val_r2` **0.5763** — baseline 대비 크게 악화(R² 0.92→0.58).
- 활성 HI 개수는 오히려 baseline보다 많음(6~14개) — 게이트가 뚜렷하게 결정을 못 내려
  느슨하게 여러 개를 켜놓은 상태로 추정.

**원인 진단(유력)**: 커널 예측값은 SOH 스케일(~0.7~1.05)을 그대로 따르는데, 원래 `x_hi`는
z-score(평균0/표준편차1)였다 — 스케일이 안 맞는 값을 그대로 넣어 최적화가 어려워졌을
가능성. 그룹 2~4개 raw HI를 스칼라 1개로 비가역 압축하면서 raw HI가 가진 정보(L0 게이트가
개별 차원을 보존해 고르던 것)를 잃은 것도 원인으로 추정.

**상태**: 코드는 v2로 완전히 재작성됐다 — 이 결과는 "왜 v2로 바꿨는지"의 근거로만 기록.

## v2 — 커널 융합, raw HI 유지 + 커널 HI 추가 (구현 완료, 실행 대기)

**로직**: v1과 그룹 fit 방식은 같지만 **raw HI(`x_hi`)를 그대로 두고, 커널 HI를 별도
블록(`x_kernel`)으로 나란히 추가**한다.

1. `build_synergy_groups.py` 그룹 중 **크기 2 이상만** 대상(크기 1은 raw HI가 이미 있어
   스킵).
2. 그룹당 Nystroem+Ridge fit(시나리오 train만) → 6개 시나리오 합쳐 2차 다중공선성 배제(0.9,
   cross-scenario) → (옵션) 시나리오별 쿼터 상한, 기본은 배제 통과분 전부 유지.
3. 최종 커널 HI의 train 기준 평균/표준편차 저장(z-score 정규화, val/test엔 적용만).
4. `SCRModel`에 **`scen_kernel_gates`**(시나리오별, raw용 `scen_gates`와 완전히 독립인
   `HardConcreteGate`) 신설 — `cap_head` 입력이 `probe_x ‖ scen_x ‖ kernel_x ‖ ...`로
   폭만 늘어남. `n_kernel_hi=0`이면 기존과 100% 동일 동작.

**실측(그룹 후보 개수만, 학습 결과는 미실행)**: `synergy_groups_k25_full_N2_groups_noleak.json`
기준 시나리오 통합 크기2+ 그룹 **91개**가 2차 다중공선성 배제 전 후보.

**상태**: 코드/단위테스트 완료(forward/backward, `n_kernel_hi=0` 하위호환, `FastTensorLoader`
자동 인식 전부 검증). 실제 데이터로 커널 피처 생성 + Phase1 학습은 아직 안 돌림 —
`docs/260820_RESULTS.md`의 "커널 융합 v2" 섹션에 실행 명령 있음.

**알려진 한계**: raw HI와 그걸로 만든 커널 HI 간 다중공선성은 검사 안 함(v1 아티팩트로
사후 측정한 결과 최댓값 0.824, 0.9 임계값은 안 넘었지만 이건 크기1 그룹 포함 구버전 기준).

## 알려진 한계 / Phase1-2 통합 전 확인할 것

1. **`--scen-k`가 실제 활성 개수를 보장하지 않는다**: `scen_k`는 `lambda_l0_auto` 공식
   (`lambda_l0 = 0.01·√(10/scen_k)`, scen_k 클수록 페널티 약화)과 플랏 컷오프 표시에만
   쓰이고, 게이트가 몇 개를 켤지 직접 강제하지 않는다. `scen_k=25`로 돌린 baseline/v0/v1
   전부 실제 활성 개수가 2~14개로 목표에 한참 못 미친다(v0가 가장 적음, 1~3개). Phase1-2를
   통합해 "정확히 k개"가 필요해지면, 지금의 독립 게이트+L0 구조로는 부족하고 예산 제약항
   추가 또는 진짜 미분 가능 top-k 메커니즘이 필요하다(상세 논의는 세션 대화 참고).
2. **그룹은 `split_seed` 하나(42)로 고정 계산**: v0/v1/v2 모두 `synergy_groups_*.json`을
   seed=42 train 분할 하나로 만들어 재사용한다. 5-seed 앙상블에 그대로 적용하면 4개 seed는
   자기 분할과 무관한 그룹 구조를 강제로 받는 셈 — 앙상블로 확장 전 seed별 재계산 또는
   그룹 안정성 확인 필요.
3. **raw-커널 다중공선성 미검사** (v2): 위 "v2" 절 참고.
4. **v0/v1/v2 전부 seed=42 1회 실행뿐**: Stage0/Stage1+2처럼 5-seed 평균으로 검증된 게
   아니라서, 위 비교표의 τ/Jaccard/포화도 개선이 다른 seed에서도 재현되는지 확인이 필요.
5. **`ref_lag`**: 세그먼트 경계가 라벨과 연동되는 구조적 리스크로 이전부터 식별돼 있으나,
   이번 v0/v1/v2 작업 범위에서는 의도적으로 제외됨(`docs/260819_RESULTS.md` 참고).
