# 260729 — HUST 충전전용(HUST-only, charge-only) k×CV×n2 비교 결과 정리

`5_model/visualize_results.py`로 만든 두 비교 결과 폴더를 정리한다. 둘 다 `q_frac_wide` 축
(`n1=35%` 고정), **HUST 데이터셋만·충전 방향만**(`data.datasets: ["HUST"]`,
`data.direction_filter: "charge"`) 사용, MLP 헤드(`mlp_hidden_dims: [128, 64]`, 25.1K 파라미터
고정), `charge_probe_m=discharge_probe_m=5` 공통이다. 방전 시나리오(`dis_hi/dis_mid/dis_lo`)는
애초에 데이터가 없으므로 모든 run에서 NaN — 표에서는 생략한다. RMSE/R² 등은 전부 test set
**hard routing**(실배포, 학습된 분류기 argmax) 기준.

두 폴더는 `scen_k_count`(HI 서브셋 크기)만 다르다:
- `0729_1339_result_comparison` — **k=15**, 4조건(`n2=9%/20%` × CV포함/제외)
- `0729_1343_result_comparison` — **k=55**, 동일 4조건

CV포함/제외 표기는 `4_hi_analysis/hi_correlation.py --exclude-cv`로 생성한 데이터 사용 여부다
(`cc_only` 폴더 = `--exclude-cv`로 CC 구간만 사용, `cv_` 폴더 = CV 구간 포함 원본).

## 3. 발견: n2=9%에서 분류기 학습이 불안정하다 (신규 이슈)

이번 8개 run의 `logs/classifier_logs.csv`를 대조해보면, **n2=9%로 돌린 4개 run 전부**에서
학습 중 val_loss가 갑자기 수~수십 배로 튀고 val_acc가 정확히 0.6667(3-클래스 중 2개만
맞히는 수준)로 붕괴하는 구간이 반복적으로 나타난다. 예:

```
# k=15, CV포함, n2=9% (최종 clf_acc 93.21%로 저장됨)
epoch 36: val_loss=0.311  val_acc=0.909
epoch 37: val_loss=7.708  val_acc=0.667   ← 붕괴
epoch 38: val_loss=19.081 val_acc=0.667
...
epoch 43: val_loss=0.090  val_acc=0.965   ← 회복(마지막 epoch)
```

k=15/CV제외/n2=9%(최종 99.95%로 저장된 "정상" run)도 58번째 epoch에서 val_loss가 1.86까지
튀는 동일한 증상을 보인다 — n2=9% 전체가 이 학습 발산 자체는 공통으로 안고 있다.

> **정정(재검증 결과)**: 처음엔 "우연히 마지막 epoch이 회복된 시점에 저장됐다"고 썼으나,
> 실제로는 틀렸다. `train_classifier.py`의 저장 조건은 `val_acc`가 갱신될 때만
> `clf_best.pt`를 저장하므로(best-val_acc 방식, 마지막 epoch 방식이 아님), CV포함·n2=9%
> run의 실제 저장 체크포인트는 **13번째 epoch(val_acc=0.9684)** — 34~42번째 epoch의
> 발산 구간과는 무관한, 학습 초반의 안정적인 지점이다. 즉 "운 나쁜 스냅샷"이 원인이
> 아니다.
>
> 진짜 원인은 `metrics.json`의 confusion matrix로 확인했다: hard routing 오류가
> **`chg_mid`↔`chg_hi` 사이에서만** 발생하고(`chg_lo`는 완벽, 0건), 이는 q_frac_wide가
> `n1=35%`에서 mid/hi 존이 기하학적으로 살짝 겹치는(overlap≈2.5%) 데서 오는 구조적
> 경계 모호성으로 보인다. 문제는 **이 오분류가 hard-routing 구조에서 증폭**된다는
> 것이다 — 오분류된 세그먼트는 전혀 다른 시나리오 전용 회귀 헤드로 들어가는데, 그
> 헤드는 그런 입력 분포를 학습한 적이 없어 예측이 근본적으로 어긋난다. 실제로 "정상"
> run(k=15·CV제외·n2=9%, 정확도 99.95%)의 confusion matrix도 방향은 완전히 동일하게
> `hi→mid` 42건(0.14%)뿐이었다 — 같은 취약점이 두 run 모두에 있지만, 이 CV포함 run은
> 그 비율이 유독 컸을(약 10%) 뿐이다. 즉 "n2=9%라서 나쁘다"가 아니라 "`n1=35%`의
> mid/hi 경계가 원래 취약한데, 이 특정 run에서 그 취약성이 유독 크게 드러났다"가 더
> 정확한 설명이다.

**원인 추정(발산 자체에 대해서는 여전히 유효)**: `train_classifier.py`는 `AdamW(lr=lr)`을
스케줄러 없이 **학습 내내 고정 LR(기본 5e-4)**로 씁니다(`5_model/train_classifier.py:256,276`)
— Phase 2 회귀의 LR 웜업 불안정성과 같은 계열의 문제로, tr_acc가 이미 97%+로 수렴한
후반부에 고정된 큰 LR이 가끔 큰 스텝을 밟아 발산시키는 패턴과 일치한다. 다만 위 정정에서
확인했듯 이 발산이 최종 저장된 체크포인트에 직접 영향을 준 것은 아니므로, 이건 "학습
과정의 불안정성" 자체는 별개로 고쳐야 할 문제이되, CV포함·n2=9% run의 217% 수치를
직접 설명하지는 않는다.

**함의**: q_frac_wide의 mid/hi 존 경계 모호성(§4 참고)이 hard-routing 구조와 결합하면,
분류 정확도가 몇 % 포인트만 나빠져도 capacity R²가 완전히 무너질 수 있다는 것을 이 run이
실증한다. n2 값 자체의 우열보다, **경계가 겹치는 축(q_frac_wide n1>1/3)을 쓰는 한 이런
증폭 리스크가 상존한다**는 게 더 근본적인 결론이다.

**권장 조치**: (1) `train_classifier.py`의 LR 스케줄 부재는 별도로 고칠 가치가 있다
(`train_scr.py`의 `--phase2-lr`처럼 `--lr` 인자는 이미 있음). (2) 더 근본적으로는, 아래
"향후 방향"에서 다루는 vqslope/vwindow 같은 라벨-독립적이고 존 경계가 겹치지 않는 축으로
옮기는 쪽이 이 증폭 문제 자체를 구조적으로 줄인다.

## 4. 향후 방향 — 세그멘테이션 축 재평가 (q_frac_wide vs vwindow vs vqslope)

§3에서 확인한 "mid/hi 경계 모호성 → hard-routing 증폭" 문제는 q_frac_wide 축 자체의 구조적
특성(`n1>1/3`일 때 존이 기하학적으로 겹침)에서 나온다. 이 문제를 근본적으로 줄이려면 축을
바꾸는 게 맞는지, 프로젝트가 갖고 있는 세 세그멘테이션 축(q_frac_wide/vwindow/vqslope)을
"현실의 무작위 부분충방전 시나리오"라는 기준으로 재평가했다.

### 세 방식의 경계 정의 방식

| 축 | 경계 정의 | 필요 정보 |
|---|---|---|
| **q_frac_wide** | `hi=[0,n1], mid=중앙, lo=[1-n1,1]` — 그 사이클 **실측 총 용량(q_tot) 대비 비율** | q_tot(그 사이클이 끝나야 아는 값) |
| **vwindow** | LFP 플래토 진입/이탈 기준 **고정 절대전압**(충전 2.80/3.38/3.47/3.60V, 방전 2.50/3.10/3.35/3.65V) + CC/CV 별도 시나리오 | 순간 전압값만 |
| **vqslope** | **순간 곡선 형상**(`|dV/dQ|<θ_flat` 또는 ICA FWHM)으로 그 자리에서 플래토 진입/이탈 랜드마크를 재검출 | 관측된 곡선 형상만 |

### 결정적 문제: q_frac_wide는 실배포 추론 시점에 정의 자체가 안 됨

q_frac_wide의 존 경계는 "그 사이클의 실측 총 용량 대비 비율"이다. 현실에서 임의 시점에
배터리를 물려 부분 충전 스니펫을 관측하는 상황(이 프로젝트가 풀려는 바로 그 문제)에서는
아직 세션이 끝나지 않았으므로 q_tot을 모른다 — q_tot을 안다는 것 자체가 사실상 SOH를
이미 안다는 것과 다름없다. 즉 q_frac_wide는 **학습(오프라인, 이미 완료된 레퍼런스
사이클로 재구성)에는 쓸 수 있지만, 실배포 추론(방금 들어온 미완료 부분 세션에 실시간
적용)에는 원리적으로 적용이 안 된다.** 단순히 "라벨과 얽혀서 평가가 낙관적으로 나온다"는
정도가 아니라, 부분관측이라는 문제 설정 자체와 정면으로 모순되는 결함이다.

### vwindow vs vqslope — 둘 다 배포 가능하지만 강건성이 다름

둘 다 q_tot 없이 순간 정보만으로 정의되므로 실배포에 쓸 수 있다. 차이는 충전 속도(C-rate)에
따른 편극(polarization) 변화에 얼마나 강건한가다.

- **vwindow(절대전압 고정)**: 같은 물리적 상태(예: 플래토 중심)라도 C-rate가 다르면
  IR강하/편극 때문에 측정 전압 자체가 위아래로 밀린다. 급속충전과 완속충전 세션에서
  "3.47V"가 실제로는 다른 SOC/열화 상태를 가리킬 수 있다 — 실제 필드에서는 충전기·
  프로토콜이 균일하지 않으므로 현실적인 리스크다.
- **vqslope(형상 기반)**: 절대 전압값이 아니라 "지금 곡선이 평탄한가/급한가"라는 상대적
  형상으로 판정하므로, 편극으로 곡선 전체가 위아래로 밀려도 플래토 구간은 여전히 상대적으로
  평탄하게 보인다 — 속도 변화에 vwindow보다 구조적으로 더 강건하다. vwindow가 프로토콜
  의존성 문제(다단계 CC에서 비단조) 때문에 데이터 피팅 방식을 버리고 고정 전압으로 간 것과
  정확히 같은 이유로, vqslope는 그 고정 전압조차 버리고 형상 검출로 간 것이다 — 계보상
  vqslope가 vwindow의 문제의식을 한 단계 더 밀고 나간 버전이다.

다만 vqslope는 실패 모드가 있다(자체 docstring에 명시) — 관측 창이 너무 짧거나 노이즈가
심해서 플래토 진입/이탈 자체를 못 찾으면 그 방향의 3존이 통째로 스킵된다. 극단적으로 짧은
필드 세션(예: 5분 꽂았다 뺌)에서는 vwindow가 "일단 순간 전압으로 무조건 분류는 된다"는
점에서 더 안전할 수 있다.

### 종합 평가

| 기준 | q_frac_wide | vwindow | vqslope |
|---|---|---|---|
| 실배포 추론 가능 여부 | ❌ (q_tot 필요) | ✅ | ✅ |
| C-rate/편극 변화 강건성 | 해당 없음(추론 불가) | 낮음 | 높음 |
| 화학종/벤더 이식성 | 해당 없음 | 낮음(전압값 재튜닝 필요) | 중간(θ_flat 정도만 재튜닝) |
| 극단적으로 짧은 관측에서의 안정성 | 해당 없음 | 높음(항상 분류됨) | 낮음(검출 실패 시 존 전체 소실) |
| 다단계 CC 프로토콜 강건성 | 중간 | 높음(이미 이 이유로 피팅→고정 전환) | 높음(형상 자체가 프로토콜 무관) |
| mid/hi 존 경계 겹침(§3의 217% 문제) | 있음(`n1>1/3`) | 없음(전압 구간이 서로 배타적) | 없음(head/plateau/tail이 순서상 배타적) |

**결론**: "현실의 무작위 부분충방전"이라는 기준에서는 q_frac_wide는 후보에서 사실상
제외해야 하고(오프라인 분석 전용으로만 위치시켜야 함), vwindow와 vqslope 중에서는
vqslope가 이론적으로 더 현실에 적합하지만 매우 짧은 스니펫에서의 검출 실패 리스크가
실사용 안정성의 아킬레스건이다. 이상적으로는 vqslope를 메인으로 쓰되, 플래토 검출 실패
시 vwindow의 고정 전압 창으로 폴백하는 하이브리드가 "이론적 강건성 + 실패 안전성"을 둘 다
잡는 방향일 수 있다 — 다만 이건 설계 확장이 필요한 별도 작업이다. §3에서 실측한
mid/hi 증폭 문제도, vwindow·vqslope는 존 정의가 서로 배타적이라(전압 구간이 겹치지
않거나, head/plateau/tail이 곡선 진행 순서상 겹칠 수 없음) 구조적으로 재발 가능성이
낮다는 점도 축 이전을 지지하는 근거다.

## 종합

1. **CV 구간을 포함하는 쪽이 4개 비교쌍 중 3개에서 확실히, 1개(k=15·n2=9%)는 CV포함
   여부와 무관한 mid/hi 라우팅 증폭 문제로 판단 보류** — CV 구간을 버리는 게
   (`--exclude-cv`) 무조건 이득은 아니고, 오히려 정보를 버리는 쪽에 가깝다는 근거가
   쌓였다.
2. **k=15가 k=55를 모든 지표에서 압도** — sparse HI 선택이 유효하다는 `260728_RESULTS.md`의
   결론이 HUST 충전전용 조건에서도 그대로 재현됨.
3. **n2=9% 조건 4개 전부에서 분류기 학습 발산이 관측되지만, k=15·CV포함·n2=9%의 처참한
   결과(R²=0.20)는 그 발산이 아니라 q_frac_wide의 mid/hi 존 경계 모호성이 원인**이었다
   (§3 정정 참고). n2 값 자체의 우열을 논하기 전에, 축 자체를 vwindow/vqslope로
   옮기는 게 더 근본적인 해법으로 보인다(§4).
