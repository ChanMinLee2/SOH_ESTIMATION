## Q001. 모델에게 각 세그먼트가 어떤 데이터셋(MIT/HUST/TJU/CALCE) 출신인지 알려줘도 괜찮은가? (배터리 전문가 리뷰어 관점)

**A**: 명시적 dataset_id를 모델 입력으로 주면 안 됨 — 실배포엔 없는 정보라 "화학종
무관 보편성"(§4 주장 A) 주장을 스스로 무너뜨림. 단, 이미 쓰는 cap_init(정격용량)이
데이터셋별 범위가 안 겹쳐서(MIT/HUST/CALCE 1.0~1.4Ah vs TJU 3.2Ah) 사실상 화학종
프록시가 됨 — 실배포엔 정당한 입력이지만 논문엔 한계로 명시 필요.

관련: `docs/260903_RESULTS.md` §4, `5_model/models/scr_model.py`(dataset_id는
평가 breakdown에만 쓰고 모델 입력엔 미사용)

## Q002. 지금 모델이 SOH(0~1)를 직접 출력하나, 아니면 용량(Ah)을 출력하고 SOH를 따로 계산하나?

**A**: SOH 비율(0~1)을 직접 출력. `segment_dataset.py`의 target 자체가
`capacity_Ah/cap_init_Ah`이고, `scr_loss.py`의 MSE도 이 SOH 스케일에서 계산됨.
Ah값은 필요할 때만 `SOH_pred × cap_init`으로 사후 역산 — cap_init은 예측값이
아니라 셀별 실측 1사이클 용량(이미 아는 값).

관련: `5_model/datasets/segment_dataset.py`, `5_model/training/scr_loss.py`

## Q003. 4개 데이터셋 사용 시 R²는 오르는데 RMSE/MAE 같은 오차 지표는 같이 오르는(나빠지는) 비일관적 모습은 왜 생기나?

**A**: R²=1-Σ(y-ŷ)²/Σ(y-ȳ)²는 **그 test set 자체의 타깃 분산이 분모**인 상대
지표. TJU(3개 온도군이 서로 다르게 열화)·CALCE가 섞이며 test set의 SOH 분산이
LFP만 있을 때보다 커지면, 절대오차(RMSE/MAE)가 같이 늘어도 분산이 더 크게 늘면
R²는 오히려 올라감 — 모순 아님. 구성이 다른 test set 간엔 R² 단독 비교 금지,
RMSE/MAE가 더 신뢰할 기준.

관련: `docs/260907_RESULTS.md` §4-3, §4-6

## Q004. 4개 데이터셋(다양한 화학종) 지원을 메인 컨트리뷰션으로 잡으면 차별성이 있나?

**A**: 약함. LFP/NMC/LCO 간 전이학습은 이미 크로우디드한 영역이고, 지금까지 한 건
"단순 풀링"뿐 — 진짜 방법론적 주장(화학종마다 독립적으로 서브셋 재선정해도 동일
방법론이 작동, 주장 A/V3-c)은 아직 미실행. TJU는 기존 공개 데이터셋, CALCE는
유효 13셀뿐이라 데이터 규모도 세일즈 포인트 아님. 메인은 SCR(시나리오별 자동 HI
서브셋 선택) 방법론으로, 화학종 다양성은 그 강건성 지지 증거로 배치 권장.

관련: `docs/260903_RESULTS.md` §4-1(주장 A/B), §4-4(V3-c)

## Q005. HI 선택을 데이터셋별로도 비교해야 하나? 게이팅 모듈에 데이터셋 축을 추가하는 건 어떤가?

**A**: 데이터셋별 비교는 필요하지만 게이트에 데이터셋 축 추가는 비추천. 이유: (1)
이미 계획된 V3-c가 "화학종별 완전 독립 모델 4개" 방식이라 아키텍처 변경 없이
`datasets`를 1개로 좁히기만 하면 됨. (2) 시나리오×데이터셋(6×4) 교차는 CALCE처럼
셀 적은 쪽에서 게이트가 불안정해짐. (3) 지금 pooled 모델 게이트는 4개 화학종 평균
신호라 애초에 화학종별 선택을 안 보여줌. (4) 주장 A(방법론이 독립 적용돼도 작동)와
다른 주장이 돼버림.

관련: `docs/260903_RESULTS.md` §4-4(V3-c/V3-d)

## Q006. ISU 데이터셋 추가+균형 풀링학습(1번) vs 데이터셋별 독립학습으로 HI 선택
비교(2번, MIT/HUST/CALCE+TJU 3군), 뭘 먼저 해야 하나?

**A**: 2번 먼저. (1) 2번이 이미 합의된 주장 A 본안 검증경로(V3-c/V3-d)를 그대로
실행하는 것 — 1번(풀링 균형화)은 §4-3에서 "예비실험, 주장 A/B 검증 아님"이라 못박은
방식이라 아무리 개선해도 결국 V3-c는 별도로 필요함. (2) 2번은 기존 인프라
(`mit_only` 선례, §7-2) 그대로 재사용해 리스크 0. 1번은 TJU/CALCE 때처럼 새 통합
버그가 나올 가능성 큼. (3) 2번 결과가 나와야 화학종 다양성이 실제 서포팅 근거로
쓸만한지 판가름됨.

관련: `docs/260903_RESULTS.md` §4-1, §4-4(V3-c/V3-d), `docs/260907_RESULTS.md` §7-2
