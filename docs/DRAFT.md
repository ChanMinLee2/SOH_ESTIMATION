## Abstract (개조식)

- 문제: 부분 충방전 곡선만으로 SOH 추정 — 실배포에서는 전체 충방전 곡선을 못
  얻는 경우가 대부분(완속/급속 혼재, 사용자 습관에 따른 부분 충전)
- 접근: raw HI 64개(4개 카테고리: stat/diff/lfp/morph) + 커널 융합으로 정보
  확장(64→71~76 per scenario) + L0 게이트 기반 서브셋 선택 + SOC 구간(6개
  시나리오) 라우팅 분류기
- 데이터: MIT+HUST(둘 다 LFP, 제조사 다름), TJU(NCM), CALCE(LCO) — 실측 공개
  데이터셋 4종
- 핵심 결과 3개(⏳ 최종 수치는 Fig6/8 갱신 후 확정):
  - oracle 기준 R²=0.94~0.95대(§6 매트릭스 기준, Fig6는 구버전 수치 사용 중 — 하단
    "알려진 이슈" 참고)
  - hard 라우팅 손실 RMSE +2%대(Fig5b)
  - 화학종 간 raw-HI 선택 자카드 0.12~0.43(Fig8b) — 화학종별로 다른 서브셋을
    실제로 고른다
- **정직하게 넣을 부정적/수정 결과**: 시나리오(SOC 구간) 라벨 조건화 자체는
  일관되게 해로웠고(§6, 2×2×2 매트릭스), 원인을 코드 레벨에서 확인함(게이트당
  학습 샘플 파편화, 정보 누수 아님) — 이건 "실패"가 아니라 **조건부 게이트
  설계에 대한 일반적 시사점**(그룹이 많아질수록 그룹당 샘플이 줄어드는 대가를
  치른다)으로 포지셔닝

## 1. Introduction

### 1.1 문제 정의 (Fig 1)

![Figure 1](figures/fig1_problem_scenario_definition.png)
**Figure 1.** (a) MIT/HUST(LFP)·TJU(NCM) 세 실제 셀의 충방전 V-q_frac 곡선
오버레이. (b) 같은 세 셀의 dV/dq — 화학종·제조사별로 피크 위치·높이가
다르다(MIT/HUST는 종료 부근 급격한 피크, TJU는 중간 SOC의 완만한 피크).

- 개조식 내용:
  - SOH 추정은 배터리 관리 시스템(BMS)의 핵심 과업인데, 실제 운용 데이터는
    항상 0→100% 풀사이클이 아니라 **임의의 SOC 구간 조각(부분 충방전)**으로만
    들어옴
  - 이 조각이 화학종/제조사에 따라 모양이 다르다는 것을 Fig1로 먼저 보여줌 —
    "화학종 무관 방법론"이라는 주장의 전제(화학종마다 다르다는 사실)부터 입증
  - 이 다름 때문에: (i) 어느 SOC 구간 조각인지 모르면 어떤 특징이 의미 있는지
    판단하기 어렵고, (ii) 화학종이 다르면 같은 특징이 다르게 작동할 수 있음

  - Figure 2 자체는 정의를 real data 위에 그대로 겹쳐 보여주는 단일 예시
    — 독자가 "시나리오"를 추상 개념이 아니라 실제 곡선의 구간으로 바로 인지
  - (연결문) 이 6개 버킷이 실제로 서브셋 선택에 유용한지는 §5.3에서 검증 —
    **스포일러: 아니었음**(§6-5 기각), 여기서는 정의만

### 1.3 컨트리뷰션 요약

- 개조식 내용:
  1. 64개 raw HI(카테고리 4개)를 배터리 열화 메커니즘에 근거해 설계(§3.1)
  2. 커널 융합으로 raw HI 간 시너지를 명시적 특징으로 확장(§3.2)
  3. L0 게이트 기반 해석 가능한 서브셋 선택 — 어떤 특징이 왜 선택되는지 직접
     시각화(§4)
  4. 4개 화학종(MIT/HUST=LFP, TJU=NCM, CALCE=LCO)에 대한 견고성 검증(§5.4)
  5. **(정직한 기여)** 시나리오 조건화 게이트 설계에 대한 엄밀한 반증 실험과
     그 원인의 코드 레벨 규명 — 조건부 게이트를 쓰는 다른 연구에도 일반화되는
     시사점(§5.3, §6)

### 3.1 HI 설계 근거 (Fig 3)

![Figure 3](figures/fig3_hi_design_rationale.png)
**Figure 3.** (2026-09-13 재개정 — 2번째 개정에서 반영한 (c)(d) 통합 아이디어를
라인 대신 반투명 surface로, 그리고 편차 크기로 2개 패널로 재분리) (a) 64개 HI

surface가 2장만 겹치므로 가독성 확보.

- 개조식 내용:
  - 4개 카테고리의 물리적 정의는 본문 텍스트가 아니라 **Table 1**로 분리 —
    Figure 3는 설명이 아니라 예시/증거에 집중(카테고리 구성 막대 그래프와
    실제 synergy-group 네트워크그래프는 각각 제거/Fig4로 이동 — 후자는
    커널 융합 스토리에 속함)
  - (a)로 "64개를 그대로 다 쓰면 안 되는 이유"(다중공선성) 제시 →
    극단 중복 쌍(|r|≥0.95)이 카테고리 **내부** 블록에 집중되는 것이
    육안으로 보임 → §3.2 커널 융합의 필요성으로 자연스럽게 연결
  - (b)(c) 분리 자체가 핵심 메시지: **모든 카테고리가 시나리오에 똑같이
    민감한 게 아니다** — (b)의 두 카테고리는 SOH 트렌드가 시나리오마다
    뚜렷이 다르게 나타나고, (c)의 두 카테고리는 시나리오 무관하게 거의
    같은 모양
  - 이건 **§6-5(e)의 파편화 메커니즘과 독립적인, HI 레벨의 두 번째 증거**임
    — (c)처럼 시나리오 불변적인 HI가 존재한다는 것 자체가 "왜 시나리오
    조건화가 (평균적으로는) 별 이득이 없었는지"를 뒷받침 — Discussion §6.2에서
    반드시 교차 인용
  - 정량적 근거: 카테고리 순위는 대표 HI의 "SOH-bin 평균을 시나리오별로 낸 것의
    표준편차"로 정렬 — 자의적 판단이 아니라 데이터 기반 분리

### 3.3 라우팅 + 게이트 아키텍처 (SCRModel)

- 개조식 내용(그림 없음, 텍스트+수식 설명):
  - probe_mlp가 미지 세그먼트를 6개 시나리오 중 하나로 분류(hard) 또는
    확률분포(soft) 산출
  - raw HI 게이트: hybrid 구조 — `hi_scenario_interaction` 검정으로 시나리오
    간 유의하게 다른 HI만 전용 게이트(scen_gates), 나머지는 공유
    게이트(shared_gate)
  - kernel HI 게이트: 전량 시나리오 전용(scen_kernel_gates) — 공유 게이트
    옵션 없음(§6-5(f)에서 이 비대칭이 부분적 원인일 가능성 언급)
  - L0 HardConcrete 게이트로 이산 선택 학습(λ_l0 스케줄, warmup)
  - 최종 회귀 헤드: mlp 기본, transformer/resnet_tab/i_transformer 교체
    가능(§5.5 견고성)

## 4. Experimental Setup

- 개조식 내용:
  - 데이터셋: MIT(123셀, LFP, 1.1Ah)·HUST(77셀, LFP, 1.2Ah)·TJU(NCM)·CALCE(LCO)

    차이"로 인정(다중 실험 전체에 일관 적용) — 이 기준의 도출 근거는 부록/§8
    원문 참고

    파편화) 그대로 서술 — **Fig8**의 no scen/v4(w/o group) 비교가 이 논증의
    시각적 요약 역할
  - 왜 이게 "실패"가 아니라 기여인지: 조건부 게이트를 쓰는 다른 도메인
    연구에도 일반화되는 시사점(그룹 수를 늘리기 전에 그룹당 유효 샘플수를

    본문에서 빠지면서 근거 소스가 애매해짐, Supplementary 인용 또는 텍스트만
    재확인 필요**
