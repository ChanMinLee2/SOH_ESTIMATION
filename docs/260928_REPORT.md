## 목적

논문과 함께 코드를 공개했을 때, 처음 보는 사람도 구조만 보고 바로 이해하고 실행해볼 수
있는 상태를 만든다. 세 가지 축으로 진행했다.

1. **파라미터 단일화** — 모든 실행 파라미터를 `parameters.py` 하나에서만 관리하고,
   각 스크립트는 참조만 하게 한다.
2. **폴더 구조 = 파이프라인 스텝 순서** — 폴더 번호만 보면 전체 실행 순서(1~9)를
   알 수 있게 한다.
3. **코드 크기 축소** — 지금 실제로 쓰이는 v4 파이프라인은 그대로 두고, 더는 안 쓰는
   과거 버전·미채택 실험·죽은 설정 체계를 제거한다.

## 수행 내역

### 1) 파라미터 단일화
9개 스크립트에 흩어져 있던 CLI 기본값과 yaml 프리셋(`model_lib/config/*.yaml`,
`--model-config` 플래그)을 전부 없애고 `parameters.py` 하나로 모았다. 정리 과정에서
"같은 의미인데 이름이 달라 따로 관리되던" 값들을 통합했다:
- 시드 3종(모델 초기화/셀 분할/대조군 재배정) 기본값 → `FIXED_DEFAULT_SEED` 하나로
- `--datasets`, redundancy threshold(시너지/커널 배제) 등 중복 플래그 통합
- yaml에만 있고 코드에서 실제로는 안 읽던 죽은 키(`leak_cols`, `is_real_input`,
  `gates_from` 등), 이미 삭제된 CLI 플래그를 계속 참조하던 죽은 상수 삭제
- `--model-config` yaml 프리셋 체계 전면 폐기(재검토 결과 리팩토링 이전 코드를
  전제로 한 채 한 번도 재검증되지 않은 것으로 확인, 그중 하나는 CLI 전달 경로
  자체가 이미 조용히 깨져 있었음)

### 2) 폴더 구조 재편
`5_model/`이라는 단일 폴더에 모든 스텝(전처리~평가)이 뒤섞여 있던 구조를
`1_convert/`~`9_eval/`(스텝 번호 폴더) + `model_lib/`(여러 스텝이 공유하는
데이터셋/모델/평가 인프라)로 재배치했다. 이후 아카이브 폴더명을 `legacy_results/`로
바꾸며 생긴 번호 공백을 없애기 위해 5~9번 스텝을 한 번 더 당겼다.

### 3) 죽은 코드 제거
"지금 정식 학습 레시피(v4)가 실제로 타는 경로" 기준으로, 뒷 스텝(평가)부터 앞 스텝
(변환) 방향으로 거꾸로 훑으며 제거했다 — 뒤쪽이 앞쪽 산출물에 의존하므로 이 순서가
호환성이 깨질 위험이 가장 적다.
- v0~v3 옛 학습기 버전, 미채택 v5 실험 경로
- CNN 분류기/CNN 임베딩 전체 체인
- `SCRTrainer`(구 학습 루프)와 그에 딸린 Laplace UQ(불확실성 정량화) 체인 전체
- 비-정식 시나리오 축 8종(`common/scenario/`) — 정식 채택된 `q_frac_ref` 축만 유지
- "Bucket A"(현재 조건으로는 어떤 경로로도 절대 실행되지 않는 코드) 15개 항목 —
  게이트 그룹 축소 메커니즘, 죽은 데이터셋 필터 함수, 미사용 평가 메서드, 죽은
  I/O 유틸 함수 등
- 위 yaml 프리셋 체계 전체

**의도적으로 보존한 것("Bucket B")**: 다른 회귀 헤드(Transformer 등), 축 파라미터
변형 등 논문의 실제 ablation 실험에 쓰이는 코드는 CLI로만 닿는 비-기본 경로라도
그대로 남겨뒀다.

### 4) 문서화
처음 보는 사람 기준으로 전체 파이프라인(데이터 변환 → 전처리 → HI 추출 → 상호작용/
시너지/커널 재구성 → 모델 학습 → 평가 → SOH 출력)을 설명하는 `docs/PIPELINE.md`와
인포그래픽을 신규 작성했다.

## 검증 방법 및 결과

구조를 옮기거나 코드를 지울 때마다 컴파일/임포트 성공만으로 끝내지 않고, 가능하면
실제 데이터로 돌려 **수정 전/후가 정말 같은 결과를 내는지** 수치로 확인했다.

- 모델 학습 루프(`SCRModel`, `train.py` 등)에 손댈 때마다 원본과 동일 조건
  (seed=0, split-seed=0)으로 **전체 재학습**을 다시 돌려 최종 체크포인트 파일의
  MD5 해시를 비교했다 — 이 파이프라인은 (적어도 이 환경에서는) 완전히
  결정론적이라, 로직이 한 글자라도 실질적으로 바뀌면 MD5가 달라진다.
- 상호작용 검정/시너지 그룹/커널 HI 생성 스크립트를 고칠 때는 산출물(JSON/PKL)의
  값 자체를 기존 레퍼런스와 직접 비교했다.
- Step4(HI 추출)처럼 캐시된 데이터로는 검증이 안 되는 변경은 셀 하나를 처음부터
  재추출해 기존 결과와 비교했다.
