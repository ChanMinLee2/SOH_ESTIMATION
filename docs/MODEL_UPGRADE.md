# MODEL_UPGRADE — Phase1→분류기→Phase2 구조를 대체할 통합 아키텍처 제안

**작성일**: 2026-08-10
**전제**: 아래 3가지 목적은 그대로 유지한다.
1. **부분 사이클 사용** — 완주하지 않은 세그먼트만으로 SOH를 추정한다.
2. **시나리오별 최적화된 HI 서브셋 구성** — 충/방전×SOH 레벨(lo/mid/hi) 조합마다 다른 HI
   조합이 최적일 수 있다는 전제를 유지하고, 이를 자동으로 찾아낸다.
3. **모르는 세그먼트에 대한 시나리오 추정** — 실배포 시 "이 세그먼트가 어느 존인지"를
   라벨 없이 스스로 판단해야 한다(hard 라우팅).

이 문서는 이 3가지를 **더 잘, 더 견고하게** 달성하기 위해 지금의 `Phase1(게이트)→분류기→
Phase2(회귀)` 3단 분리학습 구조를 어떻게 바꿀지 제안한다. 코드 재작성이 아니라 **설계
문서**이며, §6에 기존 코드베이스에서 점진적으로 옮겨가는 경로를 별도로 제시한다.

---

## 0. 왜 지금 구조를 바꿀 필요가 있는가 — 이번 세션에서 실측으로 확인된 근거

아래는 전부 이 프로젝트 자신의 로그·코드·실험 결과에서 나온 것이다(추측이 아님).

1. **Phase 2가 Phase 1 대비 뚜렷하게 개선되지 않는다.** `0809_1010_p1_...`(Phase1)과
   `0809_1118_p2_...`(Phase2) 로그를 직접 대조한 결과, 두 phase의 최종 val R²가 각각
   ~0.953·~0.952로 사실상 동률이었다(노이즈 범위 안). Phase 1도 이미 MSE 손실을 포함해
   회귀 헤드를 같이 학습하기 때문에, "게이트 고정 후 회귀만 다시 학습"하는 Phase 2가
   별도 단계로서 주는 순이익이 이 실측 기준으로는 작다.
2. **얇은 존은 `min_pts`에 취약하다(§14, `docs/260810_RESULTS.md`).** n2를 줄이면
   `chg_lo`/`chg_mid`/`dis_hi` 존이 통째로 사라지는 현상을 실측했다(HUST 77/77셀 영향).
   손으로 만든 통계 HI(`stat_*`)는 `n<min_pts`이면 전부 NaN으로 떨어지는 hard cutoff라,
   "부분 사이클"이 짧아질수록 이 구조 자체가 깨진다 — 목적 1(부분 사이클 사용)과 정면으로
   부딪힌다.
3. **hard 라우팅에 정확도 손실(routing gap)이 있다** — oracle(정답 존을 아는 상태)과
   hard(분류기가 예측한 존) 사이에 성능 차이가 있고, `metrics.json`에 `routing_gap_pct`로
   이미 추적되고 있다. 지금 구조는 분류기가 **한 번 틀리면 그 세그먼트는 완전히 다른
   HI 서브셋(다른 게이트)으로 라우팅**되는 hard-argmax라, 라우팅 오류가 그대로 큰 회귀
   오류로 증폭된다.
4. **raw 곡선 융합(구a/구b/방안1/신규a, `docs/260804_RESULTS.md`)이 baseline을 일관되게
   못 이긴다.** 4방식 중 공정 비교에서 baseline을 확실히 이긴 조합은 5개 중 1개(q_abs)뿐.
   단순 concat 방식의 raw-HI 융합이 구조적으로 약하다는 신호다.
5. **`morph` HI(6종)는 그 셀의 BOL(신품) 곡선이 별도로 저장돼 있어야만 계산된다**(직전
   세션에서 확인, `hi_correlation.py:2074-2086`) — 배포 시 그 셀의 최초 이력이 없으면 이
   6개 피처는 통째로 NaN이 된다. "모르는 세그먼트"라는 목적 3과 부분적으로 충돌한다.
6. **MIT+HUST를 도메인 정렬 없이 그냥 풀링한다** — 최근 검토한 Gong 외(*J. Energy
   Storage* 150:120566, 2026)는 이런 이종 데이터셋 결합 시 MMD로 피처 분포를 맞추는데,
   이 프로젝트는 그 정렬 항이 없다(§8-5 실험 9가 이걸 검증 중).

이 6가지는 전부 "성능이 나쁘다"가 아니라 **"지금 구조가 3대 목적을 달성하는 방식이
비효율적이거나 깨지기 쉬운 지점이 어디인지"**를 가리킨다 — 아래 제안은 이 6가지를
하나씩 겨냥한다.

## 1. 현재 아키텍처 요약 (비교 기준)

```
[원시 세그먼트 V/I/t] ──► 66-HI 계산(hi_compute.py, hand-crafted)
                              │
        Phase 1 (train_scr.py --phase 1)
        ├─ direction probe gate ×2 (charge/discharge, HardConcreteGate(N_HI))
        ├─ scenario gate ×6 (충/방전×lo/mid/hi, HardConcreteGate(N_HI) 각각)
        ├─ (classifier.type=cnn 이면) RawCNN(raw V/I/t → 3D) + 보조손실
        └─ loss = MSE(회귀) + CE(존 분류) + L0(게이트 희소성, cost-weighted)
                              │  (게이트 JSON으로 저장, 고정)
        분류기 (train_classifier.py, Step 7)
        └─ CNNProbeClassifier/MLPProbeClassifier: "이 세그먼트가 어느 존인가"를
           예측(hard 라우팅용) — Phase 1과 별도 CE 학습
                              │  (분류기 체크포인트 고정)
        Phase 2 (train_scr.py --phase 2)
        └─ 게이트·분류기 전부 frozen, cap_head(mlp/transformer/resnet_tab)만
           선택된 HI로 SOH 회귀 재학습 (+선택적 raw CNN/flat 융합)
                              │
        평가 (test_scr.py) — oracle/hard/soft 3가지 라우팅 기준 평가
```

**핵심 특징**: 3단계가 **순차적으로 완전히 분리**돼 있고, 뒷 단계는 앞 단계 출력을 고정된
입력으로만 받는다(gradient가 단계를 넘어 흐르지 않음). 게이트는 사전에 정의된 6개 존
분류 체계에 종속돼 있다.

## 2. 제안 아키텍처 — "Sparse Soft-MoE" 단일 모델

### 2.1 핵심 아이디어 한 줄 요약

**"게이트로 자르고 → 분류기로 나누고 → 회귀기로 맞추는" 3단 파이프라인을, "인코더 →
전문가별 희소게이트 → 소프트 라우팅 → 회귀"가 **하나의 모델 안에서 end-to-end로
공동학습**되는 Sparse Mixture-of-Experts(MoE) 구조로 바꾼다.** 3대 목적은 사라지지
않고, 아래처럼 **각각 명시적인 서브모듈로 재배치**된다.

| 기존 목적 | 기존 구현 | 제안 구현 |
|---|---|---|
| ① 부분 사이클 사용 | 66개 hand-crafted HI(고정 `min_pts` cutoff) | HI 유지 + **가변 길이 raw 시퀀스 인코더**(마스킹, cutoff 없음)를 병행 입력 |
| ② 시나리오별 HI 서브셋 | 6개 고정 존 × `HardConcreteGate(N_HI)`(하드 0/1) | **N_expert개 학습된 전문가 게이트**(존 6개로 초기화 가능, 이산 라벨에 안 묶임) — 여전히 L0로 희소 |
| ③ 미지 세그먼트 시나리오 추정 | 별도 학습된 hard-argmax 분류기(Step 7) | **소프트 라우팅 게이트**(같은 모델 안, 온도 조절 가능한 softmax/Gumbel-softmax) — 회귀 손실로 직접 학습됨 |

### 2.2 블록 다이어그램

```
                         ┌─────────────────────────────┐
raw V,I,t(세그먼트) ────►│  A. 공유 인코더 (raw branch)  │───► e_raw (d_raw)
  (가변 길이, mask)      │  RawCNN/1D-Transformer,      │
                         │  padding+attention mask      │
                         └─────────────────────────────┘
                                        │
hand-crafted 66 HI ─────► [x_hi] ───────┤ (그대로 병행 입력 — 폐기 아님)
  (min_pts 미달 시 NaN                  │
   마스크로 표시, 값은 0 대체)          ▼
                         ┌─────────────────────────────┐
                         │  B. 라우팅 게이트 네트워크     │
                         │  g = softmax(MLP([e_raw,      │
                         │      pooled(x_hi), direction]))│───► g ∈ Δ^(N_expert-1)
                         │  (온도 τ로 hard↔soft 조절)     │      (세그먼트별 전문가 가중치)
                         └─────────────────────────────┘
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
            ┌───────────────┐   ┌───────────────┐   ┌───────────────┐
            │ Expert 1       │   │ Expert 2       │   │ Expert N_expert│
            │ HardConcreteGate│  │ HardConcreteGate│  │ ...            │
            │ (N_HI) + 소형   │   │ (N_HI) + 소형   │   │                │
            │ 회귀 헤드        │   │ 회귀 헤드        │   │                │
            └───────┬───────┘   └───────┬───────┘   └───────┬───────┘
                    │ soh_1              │ soh_2              │ soh_N
                    └───────────────────┬┴───────────────────┘
                                        ▼
                         soh_pred = Σ_k g_k · soh_k   (가중합)
```

### 2.3 각 블록 상세

#### A. 공유 raw 인코더 — "부분 사이클" 강건성 담당

- 기존 `RawCNN`(§10.1, `raw_cnn.py`)을 그대로 재사용하되, **길이 정규화를 고정 48포인트
  리샘플 대신 가변 길이 + attention mask**로 바꾼다(1D conv는 padding, Transformer는
  padding mask). 지금처럼 "포인트 수가 `min_pts` 미만이면 NaN"이 아니라, **몇 개
  포인트든 있는 그대로 인코딩**하고 신뢰도가 낮다는 신호(포인트 수 자체)를 별도
  스칼라로 게이트/헤드에 넘긴다.
- 이렇게 하면 §14에서 실측한 "n2=5%에서 얇은 존이 통째로 죽는" 문제가 **아예 발생하지
  않는다** — 손으로 만든 통계 피처만 hard cutoff의 대상이고, raw 인코더 경로는 몇 점이든
  인코딩 가능하기 때문이다. 대신 hand-crafted HI(`x_hi`)는 지금처럼 유지하되 "결측
  마스크"를 명시적 입력으로 준다(값 0 + `is_valid` 비트) — 완전 폐기하지 않는 이유는
  아래 §2.4 참고.

#### B. 라우팅 게이트 네트워크 — "미지 세그먼트 시나리오 추정" 담당

- 지금의 분류기(Step 7, hard-argmax CE 학습)를 **회귀 손실로 직접 학습되는 soft 라우팅
  게이트**로 대체한다. 입력은 raw 인코더 임베딩 + pooled HI + `direction`(충/방전 부호)
  — **SOC 자체(=세그먼트가 어디 위치인지)는 입력으로 안 준다**는 원칙(이번 세션
  `docs/SOC.md`에서 다룬 "SOC 레퍼런스 순환성" 문제 회피)은 그대로 지킨다.
- 학습 초반엔 온도 τ를 높게(=거의 균등 분산, 모든 전문가를 부드럽게 씀) 시작해 점점
  낮춰(=점점 hard argmax에 가깝게) **soft→hard 커리큘럼**을 적용한다(Gumbel-Softmax
  anneal, 흔한 MoE 학습 기법). 최종적으로는 `test_scr.py`의 "hard" 평가처럼 거의 하나의
  전문가만 골라 쓰게 수렴하지만, **학습 중에는 라우팅이 틀려도 gradient가 완전히
  끊기지 않고 다른 전문가로도 흐른다** — 이게 지금 구조의 "hard 라우팅 오분류 →
  치명적 오차"(§0-3) 문제를 구조적으로 완화한다.
- 배포(추론) 시에는 top-1 또는 top-2 전문가만 activate해서(sparse inference) 지금과
  비슷한 계산 비용을 유지할 수 있다.

#### C. 전문가(Expert) — "시나리오별 HI 서브셋" 담당

- 전문가 수 `N_expert`는 **6(기존 존 개수)으로 초기화**하되 하이퍼파라미터로 열어둔다.
  초기화는 기존 6개 존 라벨로 warm-start(=지금의 Phase 1과 거의 동일하게 시작)하지만,
  학습이 진행되면서 라우팅 게이트가 **데이터가 실제로 필요로 하는 클러스터링**으로 서서히
  이동할 수 있게 한다 — `n1` 겹침 문제(SCENARIO_STRATEGY.md에서 이미 알려진 존 경계
  설계의 임의성)를 데이터 기반으로 완화하는 부수 효과가 있다.
- 각 전문가는 지금처럼 `HardConcreteGate(N_HI)` + 소형 MLP 회귀 헤드를 갖는다 — **"시나리오별
  최적 HI 서브셋"이라는 목적 자체는 그대로 유지**된다. L0 cost는 기존
  `CATEGORY_COSTS`(stat/diff/lfp/morph)를 그대로 재사용.
- 전문가 간 **HI 선택의 다양성을 유도하는 보조 손실**(기존 `hi_correlation.py`/
  `visualize_results.py`가 이미 계산하는 Jaccard/Ruzicka 유사도를 손실 항으로 승격)을
  추가해, 여러 전문가가 전부 같은 HI만 고르는 퇴화(mode collapse)를 막는다.

#### D. 최종 예측 — 가중 합

- `soh_pred = Σ g_k · soh_k` (mixture-of-experts 표준 방식, iMOE·cluster-Multi-CNN-ATTN
  논문과 같은 계열). 라우팅 확률 `g`는 그 자체로 "이 세그먼트가 각 시나리오에 얼마나
  가까운가"에 대한 **해석 가능한 산출물**이라, 지금 `routing_table.csv`/
  `confusion_matrix_*.png`가 하던 진단 역할을 대체할 수 있다.

### 2.4 hand-crafted HI를 왜 완전히 버리지 않는가

raw 인코더만으로 전부 대체하지 않는 이유는 두 가지다:
1. **해석 가능성**: 이 프로젝트의 강점 중 하나가 "어떤 HI가 선택됐는지"를 리뷰어에게
   보여줄 수 있다는 점이다(§10.5 게재 가능성 평가에서도 짚었듯, 이게 이 프로젝트의
   방법론적 엄밀성 중 하나). raw 인코더로 완전 대체하면 이 해석가능성을 잃는다.
2. **적은 데이터에서의 안정성**: hand-crafted HI는 도메인 지식이 들어간 강한 사전(prior)
   이라, 셀 수가 제한적인 상황(HUST 77셀 등)에서 raw 인코더 단독보다 더 안정적으로
   수렴하는 경향이 있다(§10.4에서 다룬 iMOE/cluster 논문 둘 다 raw/부분곡선 기반이지만
   295셀·124셀급 규모다).

즉 **"HI+raw 하이브리드"**를 유지하되, raw 브랜치가 있음으로써 HI만으로 못 잡는 저포인트
구간(min_pts 미달)을 보완하는 역할 분담이다.

### 2.5 도메인 정렬(MMD) — MIT/HUST 풀링 문제에 대한 대응

인코더 A의 출력(`e_raw`) 또는 라우팅 게이트 입력 단에 **MMD 정규화 항**(Gong 외,
2026 방식)을 추가한다: 같은 미니배치 안에서 MIT 임베딩과 HUST 임베딩의 분포 거리를
손실에 더해 두 데이터셋의 표현이 과도하게 갈라지지 않도록 유도한다. §8-5(실험 9)의
MIT-only/HUST-only 결과가 나오면, negative transfer가 실제로 확인되는 경우에만 이
항을 켜는 것으로 결정한다(불필요하면 계산 비용만 늘리는 항이므로 무조건 넣지 않음).

### 2.6 BOL 의존 `morph` 피처 개선

`morph_*`(DTW/Fréchet vs BOL)를 그 셀의 **첫 사이클 raw curve**가 아니라, **인코더
A가 만드는 임베딩 공간에서의 "그 전문가의 학습된 프로토타입 벡터"와의 거리**로 재정의
하는 옵션을 추가한다 — 셀별 BOL 저장이 필요 없어지고(콜드스타트 문제 해소), 여전히
"기준 대비 얼마나 변형됐는가"라는 morph의 원래 의도(Shi et al. 방식과 같은 계열,
`docs/SOC.md` §2.5)는 유지된다. 셀 자신의 BOL이 있으면 기존 방식도 병행 가능(둘 다
계산해서 비교해볼 가치가 있음 — 완전 대체가 아니라 옵션 추가로 시작).

## 3. 손실 함수 설계 (통합)

```
L_total = L_mse(soh_pred, soh_true)                              # 최종 회귀 목표
        + λ_l0 · Σ_k g_k · L0(expert_k gate)                     # 전문가별 희소성(라우팅 가중)
        + λ_route · L_route_aux                                  # (선택) 라우팅 보조손실 — 초반 warm-start용
        + λ_div · L_diversity(전문가 간 게이트 유사도)              # 전문가 다양성 유도
        + λ_mmd · L_MMD(e_raw | dataset)                         # (선택) 도메인 정렬
```

`L_route_aux`는 학습 초반에만 크게(기존 6-존 라벨을 약한 지도신호로 사용해 warm-start),
후반엔 0으로 스케줄링한다 — 완전히 비지도로 시작하면 수렴이 느릴 수 있어, 기존 존 정의를
"학습을 빠르게 시작하기 위한 초기화"로만 쓰고 최종적으로는 회귀 손실이 라우팅을 주도하게
한다.

## 4. 문헌 대비 포지셔닝

이번 세션에 직접 원문을 검토한 논문들과 비교하면:

| | 이 제안 | iMOE(Nat.Comm, 2026) | 클러스터 Multi-CNN-ATTN(Energy, 2026) | Gong 외(J.Energy Storage, 2026) |
|---|---|---|---|---|
| 라우팅 방식 | 학습된 soft MoE(온도 조절) | mixture-of-experts(유사 계열) | K-means 클러스터링 + ATTN 융합 | 해당 없음(단일 모델 + MMD) |
| HI 서브셋 선택 | 전문가별 HardConcreteGate(유지) | 없음(raw 기반) | 없음(raw 기반) | 없음(raw 기반) |
| 해석가능성 | HI 선택 + 라우팅 확률 둘 다 제공 | 낮음 | 낮음 | 낮음 |
| 도메인 정렬 | 선택적 MMD 추가 | 없음 | 없음 | **핵심 기여(MMD)** |
| 부분사이클 강건성 | raw 브랜치로 가변길이 지원 | 임의 SOC 구간 지원(강함) | 임의 위치·길이 지원(강함) | 해당 없음 |

**차별점**: 이 제안은 "HI 서브셋 선택 + 해석가능성"이라는 이 프로젝트 고유의 강점(다른
비교 논문들은 대부분 raw 기반이라 이게 없음, §10.5에서 이미 짚음)을 유지하면서, 라우팅
방식만 클러스터 논문의 MoE 아이디어를 가져와 hard-argmax의 약점을 보완하는 절충안이다.

## 6. 기존 코드베이스에서의 점진적 마이그레이션 경로

전면 재작성이 아니라 단계적으로 갈 수 있다 — 각 단계는 그 자체로 독립적으로 검증 가능한
중간 산출물을 낸다.

1. **1단계 — 라우팅만 soft로 바꾸기(가장 저비용, 가장 먼저 시도할 것)**: `scenario_classifier.py`의
   hard-argmax 출력을 softmax 확률로 바꾸고, `test_scr.py`의 "soft" 평가 모드(이미
   존재함)를 배포 시 기본값으로 승격한다. 새 모듈 없이 **기존 3단 구조를 그대로 두고**
   Step 7의 출력 소비 방식만 바꾸는 것이라 리스크가 가장 낮다. §0-3의 hard-routing gap이
   실제로 줄어드는지부터 확인한다.
2. **2단계 — Phase1/Phase2 통합**: §0-1에서 확인했듯 Phase2가 주는 이득이 실측상
   작으므로, `train_scr.py --phase 1`이 이미 회귀 손실을 포함한다는 점을 이용해 **Phase
   2를 완전히 없애고 Phase 1만으로 끝내는 실험**을 먼저 해본다(이미 §10.3에 있는 baseline
   대비 "Phase1 단독 평가"를 §10.3에서 제안한 대로 실행 — 별도 코드 추가 없이 검증 가능).
3. **3단계 — raw 인코더의 가변 길이 지원**: `raw_cnn.py`의 고정 48포인트 리샘플을
   padding+mask 방식으로 바꾸고, `hi_correlation.py`의 `min_pts` cutoff를 raw 브랜치
   에서는 제거(HI 브랜치는 유지)한다.
4. **4단계 — 전문가 다중화(MoE 전환)**: 6개 존 게이트를 `N_expert` 파라미터로 일반화하고
   라우팅 게이트 네트워크를 새로 붙인다 — 이 단계부터 진짜 아키텍처 변경이 시작된다.
5. **5단계 — MMD/BOL 개선**: §8-5(실험 9) 결과가 실제로 negative transfer를 보여줄
   때만 MMD 항을 추가(불필요하면 생략). morph 프로토타입화는 별도 ablation으로 검증 후
   채택.

**중요**: 1~2단계는 새 아키텍처 없이 지금 코드로 바로 실험 가능하고, 이미 이 세션에서
설계한 실험 8/9와 자연스럽게 이어진다 — 여기서 나오는 결과가 3~5단계(진짜 구조 변경)에
투자할 가치가 있는지를 먼저 검증해준다.

## 7. 예상 효과와 리스크

**예상 효과**:
- hard 라우팅 오차 증폭 완화 → `routing_gap_pct` 감소 기대
- min_pts로 인한 존 소멸 문제의 구조적 해소 → n2가 작은(짧은 부분사이클) 조건에서도
  baseline과의 격차 축소 기대(§10.3 실험1/6이 겪은 문제)
- 해석가능성 유지 + MoE 특유의 "이 세그먼트가 왜 이렇게 예측됐는지"에 대한 라우팅
  확률이라는 새로운 설명 축 추가

**리스크**:
- 전문가 수 `N_expert`·온도 스케줄 등 새 하이퍼파라미터가 늘어나 튜닝 비용 증가
- end-to-end 공동학습이라 지금보다 학습이 불안정해질 가능성(mode collapse 등) — §2.3의
  다양성 손실 항으로 완화하되 완전히 없어지진 않음
- soft routing이 hard보다 추론 비용이 약간 늘 수 있음(top-k로 sparse 추론하면 완화 가능)
- 파이프라인 코드가 복잡해져 디버깅 난이도 상승 — §6의 단계적 마이그레이션으로 리스크 분산

**검증 계획**: 각 마이그레이션 단계 후 §10.3과 동일한 형식(R²/RMSE/MAPE, oracle vs hard)
으로 baseline과 비교하고, 1~2단계는 별도 실험 번호(예: 실험 10/11)로 `docs/260810_RESULTS.md`
에 이어서 기록하는 것을 권장한다.
