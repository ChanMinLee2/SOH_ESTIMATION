# 일반화 용량예측기 설계 — Schema-Agnostic HI-Token 모델

> 목표: **사용자가 HI(그리고 세그먼트 정의)만 주면**, 세그먼트 분할 granularity·HI
> 종류/개수·배터리 화학종이 달라져도 대응하는 **일반화된 용량(SOH) 예측기.**
>
> 핵심 전환: 고정 스키마 MLP(현재 SCR) → **스키마 불변(schema-agnostic) 집합-트랜스포머**
> (HI = 토큰, 세그먼트 = 연속 서술자, HI 메타데이터 조건부).

---

## 0. 현재(SCR)의 한계 = 일반화 병목

| 항목 | 현재 SCR | 일반화 목표 |
|------|----------|-------------|
| HI | **정확히 64개, 순서 고정 벡터** | 임의 개수/집합/순서 |
| 시나리오 | **2방향 × 3레벨 = 6 하드코딩** | 임의 세그먼트 분할 |
| 새 HI | 아키텍처 변경 + 재학습 | zero/few-shot |
| 화학종 변화 | 재학습 | 도메인 불변 |

MLP는 입력 차원이 고정이라 스키마가 바뀌면 못 쓴다. → **가변 길이·순열 불변** 구조가 필요.

---

## 1. 핵심 원칙

> **HI를 "고정 벡터의 한 칸"이 아니라 "메타데이터를 가진 토큰"으로 다룬다.**
> 모델은 "이 스키마에 맞춰진 함수"가 아니라 **"임의의 (HI집합, 세그먼트구성) → 용량"이라는 함수 자체**를 배운다.

---

## 2. 입력 표현: HI 토큰

각 (세그먼트 s, HI h)를 **하나의 토큰**으로:

```
token(s, h) = [  value        : 정규화된 HI 값 (스칼라)
                 valid_mask    : 계산됨/결측 (0/1)
                 hi_embed      : HI 정체성 임베딩  (아래 ②)
                 seg_desc      : 세그먼트 서술자   (아래 ③)  ]
```

### ② HI 정체성 = 메타데이터 임베딩 (새 HI 일반화의 열쇠)
HI 이름 원-핫(❌, 새 HI 못 봄) 대신 **메타데이터 벡터**로 임베딩:
```
hi_meta(h) = [ category(stat/diff/lfp/morph) 임베딩,
               계산비용(cost),
               측정 대상(전압형상 / 미분 / plateau / 형태 …) 임베딩,
               (선택) 텍스트 설명 임베딩 ]
hi_embed(h) = MLP(hi_meta(h))
```
→ 처음 보는 새 HI라도 메타데이터가 비슷하면 **기존 HI 근처 임베딩**을 받아 즉시 활용.
사용자는 HI를 정의할 때 이 메타데이터만 채우면 된다 (`hi_registry.yaml`).

### ③ 세그먼트 = 연속 서술자 (임의 분할 대응)
"3레벨" 하드코딩 대신 각 세그먼트를 **연속값**으로:
```
seg_desc(s) = [ SoC창 중심, SoC창 폭, 방향(±1), 평균 전류율(C-rate), … ]
```
→ 3개를 5개·10개로 쪼개도 그냥 서술자 값이 달라질 뿐. 분할 granularity에 불변.

---

## 3. 아키텍처

```
raw 사이클 ─▶ [세그먼트화(전류적산)] ─▶ 세그먼트 s = 1..S (가변)
                                         각 s에 대해 계산 가능한 HI h = 1..H (가변)
                                              │
                                              ▼  토큰 집합  {token(s,h)}
                        ┌─────────────────────────────────────────────┐
                        │  Set/Transformer Encoder (순열 불변, 가변 길이) │
                        │   - HI 간 self-attention → 다중공선성 자연 처리   │
                        │   - 세그먼트 간 attention → 시나리오 관계 학습     │
                        └─────────────────────────────────────────────┘
                                              │  풀링 (attention pooling)
                                              ▼
                                   Capacity Head ─▶ SOH (상대 용량)
```

- **인코더 1단계 (DeepSets)** 로 시작 → 안정화 후 **Transformer(attention)** 로 업그레이드.
- **다중공선성**: attention이 상관된 HI 그룹 중 대표에 attend하도록 학습 → 독립 L0 게이트보다 우아하게 dedup. (오늘 겪은 문제의 근본 해법)

---

## 4. 동적 라우팅 = 토큰 게이트 (일반화된 DFR)

"어떤 HI를 계산할지"를 **토큰별 게이트**로:
```
gate(s,h) = σ( router( hi_embed(h), seg_desc(s), z_context ) )
```
- 게이트가 **HI 임베딩·세그먼트 서술자의 함수** → 새 HI/세그먼트에도 일반화되는 라우팅.
- 비용가중 L0로 "계산할 가치" 학습 (현재 프레임워크의 일반화).
- 현재의 "방향별 probe / scen 게이트"는 이 구조의 **특수 케이스**.

---

## 5. 학습 전략: 스키마 증강 (일반화의 실질 동력)

고정 스키마에 과적합되지 않도록 **매 배치 스키마를 랜덤 변형**:
- **HI 부분집합 랜덤 드롭/샘플** (feature-set dropout)
- **세그먼트 분할 수 랜덤 변경** (3↔5↔N)
- (가능하면) **여러 화학종/데이터셋 혼합**

→ 모델이 "특정 64개 HI·3레벨"이 아니라 **"주어진 임의 구성에서 용량 뽑기"** 를 배운다.
이게 "사용자가 HI만 정의하면 대응"을 가능케 하는 핵심.

---

## 6. 도메인(화학종) 강건성

- **타깃 = 상대 SOH** (초기 용량 대비 비율), 절대 Ah ❌ → 정격·화학 스케일 불변.
- **셀별 정규화** + HI값의 상대화(BOL 대비 변화율) → 도메인 편차 흡수.
- 다화학 공동 학습 + (선택) 도메인 적대/불변 표현.

---

## 7. 현재 SCR에서의 마이그레이션 경로

버리는 게 아니라 **단계적 일반화**:

| 단계 | 변경 | 얻는 것 |
|------|------|---------|
| **M1** | HI 벡터 → **HI 토큰 + DeepSets 인코더** | 가변 HI 개수/집합 (최대 잠금해제) |
| **M2** | 3레벨 → **연속 seg_desc** | 임의 분할 |
| **M3** | HI 원-핫 → **메타데이터 임베딩** (`hi_registry.yaml`) | 새 HI zero-shot |
| **M4** | 고정 학습 → **스키마 증강 + 상대 SOH** | 패턴·화학 일반화 |
| **M5** | DeepSets → **Transformer(attention)** | 다중공선성·관계 처리 |

재사용: 전류적산 세그먼트화, 셀단위 분할, 정규화, 라우팅/L0 개념, 평가 파이프라인.

---

## 8. 필요한 사용자 인터페이스 (목표 UX)

사용자는 **두 개의 정의 파일**만 제공:
1. `hi_registry.yaml` — 각 HI의 {이름, 계산함수, 카테고리, 비용, 메타데이터}
2. `segment_spec.yaml` — 세그먼트 분할 규칙 (전류적산 창, 개수)

→ 나머지(토큰화·인코딩·라우팅·예측)는 스키마 불변 모델이 자동 처리.

---

## 9. 리스크 & 유의

- **집합 모델은 데이터를 더 요구** → 스키마 증강·다화학 데이터가 뒷받침돼야.
- **메타데이터 품질**이 새 HI 일반화를 좌우 → 레지스트리 설계가 중요.
- **Transformer 비용** → HI/세그먼트 수가 크면 attention 비용 관리 (선형 어텐션/샘플링).
- 초기엔 M1(토큰+DeepSets)만으로도 "가변 HI 대응"의 80%를 얻으니, **M1부터 검증** 권장.

---

## 10. 한 줄 요약

> **고정 스키마 MLP → HI를 토큰으로 보는 스키마 불변 집합 모델.**
> HI=메타데이터 토큰, 세그먼트=연속 서술자, 라우팅=토큰 게이트, 학습=스키마 증강.
> 그러면 "사용자가 HI만 정의하면 다양한 배터리 패턴에 대응하는 용량예측기"가 된다.
> 현재 SCR은 이 일반 프레임워크의 **고정 스키마 특수화**이자 검증된 발판이다.
