## 1. 배경 — 이 그림이 무엇을 설명하는가

배터리 SOH(State of Health, 건강 상태) 예측 모델입니다. 충전 또는 방전 중
**일부 구간(segment)**만 관측해서, 거기서 뽑은 64개의 수치 지표(HI, Health
Indicator)로 배터리 용량을 추정합니다. 핵심 아이디어는: 이 짧은 구간이
"충전 초반"인지 "방전 후반"인지(총 6가지 시나리오) 모델이 스스로 먼저 추정하고,
그 추정에 따라 **각 시나리오 전용으로 선택된 지표 조합**으로 최종 예측을
수행한다는 것 — 즉 하나의 고정된 지표 세트가 아니라, 상황마다 다른 지표
조합을 쓰는 구조입니다. 이 Figure 2는 그 전체 데이터 흐름(forward pass)을
한 장으로 보여주는 아키텍처 다이어그램입니다.

### 1.1 용어 미니 사전 (아래 §2에서 쓰이는 단어들)

그림에 들어갈 라벨/개념을 이해하는 데 필요한 최소한의 설명만 정리했습니다
(수식·이론적 근거는 그릴 때 필요 없으므로 생략):

| 용어 | 한 줄 설명 |
|---|---|
| HI (Health Indicator) | 측정 곡선에서 뽑은 숫자 하나하나. "입력 신호" 정도로 이해하면 됨 |
| segment(구간) | 충전/방전 전체가 아니라 그 중 짧은 일부 구간만 잘라서 본다는 뜻 |
| scenario(시나리오) | 그 구간이 "충전/방전 중 어느 SOC(충전 수준) 구간"에서 온 건지 — 6가지 경우의 수 |
| gate(게이트) | 어떤 HI를 "쓸지/버릴지" 결정하는 스위치. 스위치가 켜진 HI만 다음 단계로 전달됨 |
| shared gate vs scenario-specific gate | shared = 6개 시나리오가 스위치 하나를 공유(다 같이 켜지거나 꺼짐) / specific = 시나리오마다 독립된 스위치 |
| classifier / router | "지금 이 구간이 6가지 시나리오 중 뭔지" 추측하는 작은 판별기 |
| routing mode (oracle/hard/soft) | 그 판별기 결과를 최종 예측에 어떻게 반영할지의 3가지 방식(그림에는 이름 3개만 병렬 표시하면 됨, 차이는 그릴 필요 없음) |
| kernel HI | 여러 HI를 하나로 수학적으로 합성해 새로 만든 지표(원본 HI와 별개의 추가 입력) |
| direction | 충전인지 방전인지를 나타내는 단순 표시값 |
| cap_init | 예측의 기준이 되는 초기 용량값(참고용 숫자 입력) |
| SOH (ĉ) | 최종 출력값 — 배터리가 얼마나 건강한지(초기 대비 용량 비율) |

## 2. 필수 포함 요소 (내용은 고정 — 배치/스타일만 재작업)

아래 5개 구역과 각 구역 안의 요소를 빠짐없이 포함해주세요(첨부 참고 이미지
`fig6_arch_scr_model.png`에 전부 그려져 있으니 그대로 대조하며 옮기면 됩니다).
괄호 안 영문 라벨은 **그림에 실제로 들어갈 텍스트**(디자이너가 임의로 바꾸지
말고 아래 적힌 그대로 사용)입니다.

### 2.1 Stage 1 — Data processing
- 입력: 부분 충전/방전 구간 1개 ("Partial charge/discharge segment"), 실제
  전압-용량 곡선 1개를 작은 예시 그래프로 함께 표시
- 그 구간에서 뽑히는 **64개 raw HI**, 4개 카테고리로 색 구분:
  stat(18) / diff, dQ-dV(20) / lfp-specific(20) / morphology(6)

### 2.2 Stage A — Direction-aware probe gate (분류기)
- "Direction-aware probe gate (L0)" 박스 — 64 raw HI를 입력받아 충전/방전
  방향별로 분리된 두 개의 학습 가능한 선택 게이트(`charge_probe_gate` /
  `discharge_probe_gate`)로 일부 지표만 통과시킴
- → "Scenario router" 박스 — 통과된 지표로 작은 분류기(`probe_mlp`)가
  **6가지 시나리오**(아래 2.4 참고) 중 하나를 예측
- 학습 시에만 걸리는 보조 손실 표시: "CE loss (Phase 1 only)"
- 추론 시 3가지 라우팅 방식 뱃지: **oracle / hard / soft** (실제 배포에서
  분류기 예측을 어떻게 신뢰할지에 대한 3가지 모드 — 색으로 구분된 작은
  라벨 3개)

### 2.3 Kernel fusion (전처리 요약 — 별도 박스)
- "synergy groups → Nyström + ridge → 1 kernel HI / group" — 상관관계 높은
  raw HI들을 비선형 변환으로 압축한 "kernel HI"가 어떻게 만들어지는지 요약
  (여러 선이 한 점으로 모이는 아이콘화된 표현)
- **중요**: 이 kernel HI는 분류기(Stage A)로는 들어가지 않고, 회귀기(Stage B)
  에만 들어갑니다 — 화살표 방향을 반드시 이렇게 유지할 것

### 2.4 Stage B — Scenario-conditioned subset gates (회귀기)
- 6개 시나리오 카드(각각 작은 아이콘 + 라벨): **chg_lo, chg_mid, chg_hi,
  dis_hi, dis_mid, dis_lo** (충전 저/중/고 SOC, 방전 고/중/저 SOC)
- 각 시나리오가 두 종류의 게이트를 거침:
  1. **Raw-HI subset gate (hybrid, L0)** — "공유 게이트(shared) + 시나리오
     전용 게이트(scenario-specific)"가 섞인 구조. 일부 raw HI는 모든
     시나리오가 같은 게이트 값을 공유하고, 나머지는 시나리오마다 독립적으로
     선택됨 (게이트 확률을 짙은/옅은 색 블록 히트맵으로 시각화)
  2. **Kernel-HI subset gate (L0)** — 시나리오마다 **완전히 독립적인**
     게이트(공유 없음)
- (주의) 두 게이트 종류의 "공유 여부" 차이가 이 구조의 핵심 메시지 중
  하나이므로, 시각적으로 명확히 구분되게 해주세요(예: hybrid는 두 색 톤,
  kernel은 단일 톤).

### 2.5 결합 + Swappable head + 출력
- 결합 지점(⊕ 기호): probe_x ⊕ scen_x ⊕ kernel_x ⊕ direction ⊕ cap_init
  (Stage A/B에서 선택된 지표들 + 방향 플래그 + 초기 용량 기준값을 모두 이어붙임)
- "Swappable head" 박스 — 최종 예측을 수행하는 회귀 헤드는 교체 가능한
  모듈임을 표시: **MLP(default) / Transformer / ResNet-tab.** 3개를 겹친
  카드로 표현(하나가 기본, 나머지는 대안이라는 느낌)
- 출력: **Predicted SOH (ĉ)** — 실제 용량-사이클 곡선 예시 그래프 1개를
  작은 인셋으로 포함

### 2.6 범례 (Legend)
- 화살표 종류 2가지: 실선(일반 데이터 흐름) / 점선(Phase 1 한정 보조
  그래디언트, CE loss 쪽)
- 색 인코딩 2가지: "high gate probability (selected)" / "low gate
  probability (pruned)"

### 2.7 하단 요약식 (옵션, 공간 되면 포함)
- `x_hi(64) → probe_x, scen_x, kernel_x ⊕ (dir, cap_init) ⇒ cap_head → SOH`
  형태의 한 줄 요약 — 그림 하단 캡션성 텍스트로

## 3. 수식과의 표기 일치 (중요)

본문에 이 그림 바로 아래/위로 수식 2개가 나옵니다:
1. HardConcrete 게이트 확률식 (L0 게이트가 어떻게 "선택/제외"를 미분 가능한
   형태로 근사하는지)
2. 전체 손실함수: `MSE + λ_scen·CE + λ_l0·L0 penalty`

그림 안의 변수명(`probe_x`, `scen_x`, `kernel_x`, `charge_probe_gate` 등)은
**본문·수식의 표기와 반드시 동일하게** 유지해주세요 — 디자이너가 임의로
약어를 바꾸거나 보기 좋게 다른 이름으로 교체하면 안 됩니다. 변경이 필요하다
싶으면 반드시 저희에게 먼저 확인 요청해주세요.

## 5. 디자인 방향

- **톤**: 저널(IEEE Transactions on Transportation Electrification 또는
  Journal of Power Sources) 투고용 — 장식적이지 않고 정보 밀도 높은 학술
  다이어그램. 과도한 그라디언트/그림자/3D 효과 금지.
- **팔레트**: 같은 논문의 다른 그림들이 "탈채도(desaturated), 저채도 다크톤"
  색 기조로 이미 통일돼 있습니다 — 아래 핵심 색만 유지되면 나머지 보조색은
  디자이너 재량으로 조정 가능:
  - SOC-구간 3색(시나리오 의미와 직결, 반드시 유지): `#3A6178`(저SOC 계열),
    `#A9863F`(중SOC 계열), `#96473A`(고SOC 계열)
  - 라우팅 3모드(oracle/hard/soft)도 위와 동일한 3색 재사용 중 — 그대로
    유지하면 "같은 색=같은 의미" 일관성이 생김
  - 잉크/텍스트: `#1A1A1A`(본문), `#5C5C5C`(보조), 배경 흰색
- **타이포그래피**: Arial(또는 호환 산세리프) 계열, 저널 2단 컬럼에서도
  라벨이 깨지지 않을 정도의 크기 위계
- **흑백 인쇄 대응**: 많은 리뷰어가 흑백으로 출력합니다 — 색만으로 구분되는
  요소(특히 게이트 확률 히트맵, SOC-구간 3색)는 명도 차이 또는 패턴(해칭 등)
  으로도 구분 가능하게 이중 인코딩 해주세요.
- **정리/간결화 환영**: 첨부 참고 이미지는 6개 시나리오 카드가 다소 반복적으로
  나열돼 복잡해 보입니다 — 의미 손실 없이 시각적으로 더 정돈된 방식(예:
  6개를 한 그룹으로 묶고 대표 1개만 상세히 보여준 뒤 "×6"로 표기하는 등)으로
  재구성하는 것은 환영합니다. 다만 "공유 게이트 vs 시나리오 전용 게이트"
  구분이 사라지면 안 됩니다.

## 8. 진행 방식 제안

1. 1차 레이아웃 스케치(러프) 공유 → 저희가 내용 누락/오표기 검토
2. 본 작업 → 1차 드래프트
3. 수식·본문 표기와 최종 대조 후 1~2회 수정
4. 최종 벡터+PNG+PDF 납품
