# PLOTS — 컨트리뷰션 뒷받침용 플랏 후보 리스트

**컨트리뷰션**: 64개의 HI(Health Indicator) 정의 + 커널 시스템을 통한 정보 확장을
회귀/분류 모델에 넣어, 미지의(unknown) 세그먼트에 대해 특징적인 시나리오를
순차적으로 구분하고, 그 시나리오에 최적화된 서브셋을 기반으로 학습하는
프레임워크(SCR).

상태 표기: [✅기존] 이미 만든 도구/산출물로 즉시 생성 가능 · [🔧신규] 데이터는
있지만 플랏 코드가 새로 필요 · [⏳실험필요] 데이터 자체가 아직 없음.

---

## A. 문제 정의 / 동기 (왜 이 문제가 어려운가)

1. **LFP/NCM/LCO 배터리 열화 곡선 비교 플랏** — 화학종별 V-Q 곡선 오버레이(초기→말기 색상 그라데이션) + 용량 열화 곡선. 이유: "동일한 방법론이 화학종 무관하게 작동해야 한다"는 주장의 전제 자체가 화학종마다 열화 패턴이 다르다는 걸 먼저 보여줘야 함. [✅기존 — `plot_cell_cycles.py`/`plot_all_mit_cells.py`, MIT/HUST/TJU/CALCE 전부 이미 생성됨]

2. **동일 셀의 시나리오별(SOC 구간별) V-t/V-Q 오버레이 단일 사이클 예시** — 색상 밴드로 chg_lo~dis_lo 6구간 표시. 이유: "시나리오"라는 개념 자체가 물리적으로 뭘 의미하는지(SOC 구간에 따라 곡선 형태가 실제로 다르다는 것) 독자에게 직관적으로 보여주는 도입부 그림. [✅기존 — `seg_diagnose.py --mode segment`]

3. **레퍼런스 노이즈(q_frac_ref) 유무/재보정 유무 비교 플랏** — 이미 만든 offset/calibration 비교. 이유: "미지의 세그먼트"라는 표현이 실배포 환경의 노이즈 있는 SOC 추정을 가정한다는 것을 정당화. [✅기존 — `3_integrity/plot_qfref_noise_offset.py`]

## B. HI(64개) 설계 근거

4. **HI 카테고리별(stat/diff/lfp/morph) 개수·정의 요약 테이블/다이어그램** — 각 카테고리가 어떤 물리량(전압 통계/DVA-ICA/LFP 특유 평탄구간/DTW 형태유사도)을 포착하는지 트리 다이어그램. 이유: "64개 HI 정의"가 임의가 아니라 배터리 열화 메커니즘에 근거한다는 것을 보여주는 핵심 근거. [🔧신규 — `hi_schema.py`의 카테고리 정의 시각화만 하면 됨, 가벼움]

5. **HI-SOH 단변량 상관 히트맵(카테고리×시나리오)** — 이미 `hi_correlation.py`가 만드는 상관 히트맵. 이유: 개별 HI가 SOH와 실제로 관련있다는 최소 근거(게이트가 뭘 고르든, 애초에 그 HI들이 신호를 담고 있다는 사전 검증). [✅기존 — `hi_correlation.py`]

6. **HI 중복성(redundancy) 클러스터맵** — `build_synergy_groups.py`의 편상관 기반 그룹화 이전 단계 상관 구조. 이유: 왜 "64개를 그대로 다 쓰지 않고" 커널 그룹으로 묶는 동기가 필요한지(다중공선성) 보여줌 — 커널 시스템 도입의 필요성 자체를 정당화하는 플랏. [✅기존 — `plot_synergy_groups.py`]

## C. 시나리오(SOC 존) 정의 및 세그먼트 커버리지

7. **6개 시나리오 존 경계 다이어그램** — q_frac 축 위에 chg_lo/mid/hi, dis_hi/mid/lo 존 위치·겹침을 막대로 표시. 이유: "시나리오를 순차적으로 구분한다"의 "시나리오"가 정확히 뭘 의미하는지 정의하는 필수 그림.

8. **존 포인트 커버리지 실측표/플랏** — "6개 존 전부 100.000%" 확인한 것. 이유: 세그멘테이션이 데이터를 빠뜨리지 않고 전량 커버한다는 방법론적 엄밀성 증거. [✅기존 — n2-range 실험 산출물]

## D. 커널 시스템에 의한 정보 확장

9. **raw HI 개수 vs 커널 HI 개수 비교 막대** — 64(raw) → 59~92(kernel, 그룹 결과에 따라 다름) 확장 폭을 데이터셋/그룹별로. 이유: "정보 확장"이 실제로 일어났다는 정량적 근거.

10. **커널 그룹 구성 예시(대표 그룹 몇 개의 raw HI 조합 + 그 그룹의 예측력)** — `build_kernel_group_features.py`의 `train_r2`로 정렬해 상위 몇 개 그룹의 멤버 구성 표. 이유: 커널이 "그냥 숫자를 늘린 것"이 아니라 물리적으로 말이 되는 조합(예: DVA피크+plateau폭)을 만들어낸다는 것을 보여줌 — 정보 확장의 질적 근거.

11. **raw HI 단독 예측력 vs 커널 HI 예측력 분포 비교(박스플롯)** — 각 피처의 `train_r2`(또는 단변량 상관)를 raw/kernel 두 그룹으로 나눠 분포 비교. 이유: 커널 융합이 개별 raw HI보다 더 강한 신호를 만든다는 정량적 증명. [🔧신규 — kernel_group_features_*.pkl의 `train_r2` + raw HI 상관값만 있으면 바로 가능]

## E. "미지의 세그먼트 → 시나리오 순차 구분" (분류/라우팅 성능)

12. **분류 정확도 confusion matrix(6×6, hard 모드)** — 이유: "순차적으로 시나리오를 구분한다"는 claim의 직접 증거 — 모델이 실제로 미지의 세그먼트를 올바른 SOC 구간으로 잘 분류하는지. [✅기존 — `figures/confusion_matrix_test_hard.png`]

13. **oracle→hard→soft 라우팅 성능 저하율 비교** — 정답 라우팅(oracle) 대비 실제 분류기 라우팅(hard/soft) 시 RMSE 저하 % 막대. 이유: "순차적 구분"이 실전에서 얼마나 비용을 치르는지 — 실배포 신뢰성 지표. [✅기존 — 이미 여러 표에 텍스트로 있음, 시각화만 안 됨]

14. **분류 정확도 vs 사이클(열화 진행도) 추이** — 셀 수명 초반/말기에 분류 정확도가 달라지는지. 이유: 열화가 진행될수록 존 경계 근처 데이터가 애매해질 수 있어, 라우팅 강건성의 시간축 검증. [🔧신규 — test_predictions.csv + routing 정보로 재집계 필요]

## F. 시나리오별 최적화된 서브셋 (게이트 해석가능성) — **가장 핵심**

15. **HI 선택 매트릭스(raw+kernel, 시나리오×HI 히트맵 + 커널 구성비)** — 이유: "시나리오에 최적화된 서브셋"이라는 claim의 **직접적 시각 증거** — 어떤 HI가 어느 시나리오에서(만) 선택되는지 한눈에. [✅기존 — `plot_hi_selection_matrix.py`]

16. **시나리오 간 선택 HI 자카드 유사도 히트맵(raw/kernel 둘 다)** — 이유: "시나리오별로 진짜 다른 서브셋을 쓰는가"를 정량화(대각선 1.0, 비대각 낮을수록 시나리오 특이적). [✅기존 — `visualize_results.py`]

17. **선택된 HI의 카테고리 구성 — 시나리오별 막대(stacked)** — 예: chg_lo는 diff 계열이 많고 dis_lo는 lfp 계열이 많은지. 이유: 시나리오별로 "왜" 다른 HI가 선택되는지에 대한 배터리 물리 해석 — 논문 discussion에 필수적인 해석 자료. [🔧신규 — 15번 데이터로 재집계]

18. **대표 선택 HI 1~2개의 실제 곡선(시나리오별)** — 예: `diff_dqdv_area_chg_lo`가 실제로 어떤 모양이고 SOH와 어떻게 상관되는지 산점도. 이유: 추상적인 "선택됨"을 넘어 "이 HI가 실제로 이렇게 생겼고 이래서 유용하다"는 정성적 스토리텔링. [🔧신규]

19. **게이트 확률(gate_prob) 분포 히스토그램(raw vs kernel)** — L0 게이트가 0/1로 얼마나 깔끔하게 이산화됐는지. 이유: 학습이 실제로 "선택"을 하고 있다는 방법론적 건전성 증거. [🔧신규 — gates/*.json의 확률 분포만 히스토그램으로]

## G. 최종 SOH 회귀 성능

20. **SOH 예측 산점도(true vs pred, oracle/hard)** — 이유: 기본적인 정확도 증거. [✅기존]

21. **대표 셀 용량곡선 비교(예측 vs 실측, 시나리오별 오버레이)** — 이유: "숫자"가 아니라 "곡선 형태"로 예측 품질을 직관적으로 전달 — 리뷰어가 가장 먼저 보는 그림 중 하나. [✅기존 — `capacity_curve_*.png`]

22. **오차 히트맵(용량×시나리오/사이클)** — 이유: 어떤 SOH 구간/사이클 구간에서 예측이 어려운지 세밀하게 보여줌. [✅기존]

## H. 기여도 분해 (핵심 — Ablation)

23. **v4 vs rawonly vs noscen vs 대조군2 4-way 막대(R²/RMSE)** — H1/H2를 한 그림에. 이유: "게이트가 필요하다"(H1)와 "시나리오가 필요하다"(H2) 두 핵심 주장을 한 그림으로 압축 전달 — 메인 결과 그림 후보 1순위. [⏳실험필요 — H1(대조군2)/H2(A,B) 전부 완료돼야]

24. **라벨 효과 vs 배치 효과 분리 그림(2×2 매트릭스, docs/0909_RESULTS.md 설계)** — 이유: H2를 둘러싼 confound(배치 다양성 vs 라벨)를 독자에게 투명하게 보여주는, 방법론적 엄밀함을 증명하는 그림 — "confound 아니냐" 질문을 선제 차단. [⏳실험필요]

25. **HI 개수(64→66) 재사용 타당성 요약** — 이유: "왜 64개(stat_leak 제외)를 최종으로 썼는지"에 대한 근거. [✅기존]

26. **회귀 헤드(mlp/transformer/resnet_tab) 아키텍처 무관 견고성** — 이유: "프레임워크(게이트+커널)의 기여가 특정 회귀 헤드에 종속된 게 아니다"라는 일반성 증명. [✅기존(mlp/transformer만), resnet_tab 재실행 필요]

## I. 일반화 / 강건성 (조심스럽게 다룰 부분)

27. **화학종별(MIT/HUST/TJU+CALCE) 독립학습 HI 선택 비교** — 화학종별로 나란히 + Jaccard/Kendall τ. 이유: "다양한 화학종에 적용 가능"이라는 서포팅 주장의 핵심 증거(메인 컨트리뷰션이 아니라 서포팅 증거로 포지셔닝). [✅기존 도구, 3개 run 완료 — 비교 플롯 자체는 🔧신규 조합]

28. **세그먼트 길이 강건성(n2-range) 결과 — 있는 그대로 정직하게** — "직관과 반대" 결과. 이유: 부정적 결과라도 투명하게 보고하는 게 신뢰도를 높임(메인 그림이 아니라 limitation/discussion 섹션용).

## J. 효율성 / 실용성

29. **파라미터 수 vs 정확도(regression head별) 산점도** — 39.8K(mlp) vs 428.5K(transformer) 등. 이유: "가벼운 헤드로도 충분하다"는 실용적 강점 어필.

30. **인퍼런스 속도(ms/sample) 비교** — 이유: 실배포 관점에서 게이트 기반 서브셋 선택이 계산량을 줄인다는 실용적 강점 어필(단, 선택 안 된 HI를 실제로 스킵하는지는 확인 필요).
